## [2.3.1] — 2026-08-23

### Added — candidate-closure gate

An external review proposed a dozen closed-form "parameter closures" claimed
to eliminate the framework's remaining calibration inputs — Weinberg angle,
PMNS angles, cosmological constant, Hubble tension, muon g-2, VEV factor, GUT
coupling, Majorana phase, soft-SUSY scale, baryogenesis prefactor. Checking
the arithmetic before integration was the whole job: **most fail their own
claimed numbers.**

- `PM/validation/candidate_closure_gate.py` evaluates every proposal from
  SSOT inputs and records verdicts in `AutoGenerated/candidate_closures.json`:
  **9 FALSIFIED, 1 ILL_FORMED, 1 NEAR_MISS_NOTED, 1 PLAUSIBLE_UNTESTABLE,
  1 ALREADY_INTEGRATED, 1 OPEN_PROPOSAL.** Highlights:
  - the Weinberg formula `(3/8)(1 − 2/24π)` evaluates to **0.365**, not the
    claimed 0.2312 — a 58% miss presented as "sub-sigma precision"
  - the θ₁₃ formula evaluates to **0.31°**, not the claimed 8.618°
  - the Golay-capacity Λ expression evaluates to **1.17×10⁻⁶** against a
    claimed 1.17×10⁻¹²⁰ — the mantissa matches, the exponent fabricates 114
    orders of magnitude
  - the Majorana-phase expression takes √ of a negative number
  - the one arithmetic survivor (`m_soft = M_Pl·e^(−3π/2)` ≈ 2.19×10¹⁶ GeV)
    is recorded PLAUSIBLE_UNTESTABLE, because no measurement of m_soft exists
  - Vol(S⁵)=π³ vs 10π (1.3% apart, exactly π²/10) is recorded as a
    NEAR_MISS with the look-elsewhere caveat, not adopted
- Wired as a standalone pre-flight build step; report-only (`n_pass = 0` by
  construction — the gate records verdicts on proposals, it does not certify
  predictions). Per the standing rule, falsified candidates stay on the books
  so the same dead end is never explored twice.

### Notes

- The proposed Kähler–Ricci running-Re(T) sector and instanton-corrected
  W(T) carry no evaluable numbers (the per-cycle χᵢ inputs do not exist in
  this codebase) and are recorded as OPEN_PROPOSAL pending an author ruling.

## [2.3.0] — 2026-08-22

The theme of this release is that several things which looked verified were
not, and are now either verified or honestly labelled.

### Added — a cross-shadow interaction sector

The bridge sector previously had **no** cross-shadow coupling. The only metric
channel that could carry one — the off-diagonal `L1*L2*cos(theta)` — is
identically zero at the stabilised vacuum, because that vacuum sits at
`theta = 90 deg` exactly on all twelve bridge pairs. That is why the
reflection-positivity gate reports `MARGINAL_VACUOUS` rather than `PASS`.

- **`PM/gauge/topological_terms.py`** — a topological coupling that survives
  the orthogonal vacuum. Two results, both verified rather than asserted:

  - **A selection rule.** `phi ^ F_A ^ F_B` is non-zero **iff** the
    complementary index triple is one of `phi`'s seven associative triples —
    exactly **42 of 210** disjoint channels (7 triples x 6 ordered
    pair-splits). Tested in both directions: an allowed channel is non-zero
    *and* a forbidden one vanishes.
  - **The coupling is maximal at the vacuum.** It couples to the bridge *area*
    (`sin theta`) where the metric channel couples to `cos theta`:

        area route   :  5.647615e+02    maximal at theta = 90 deg
        metric route :  2.117516e-30    dead at theta = 90 deg

    The two channels are exactly complementary. Verified by two independent
    routes — the general epsilon contraction and the coassociative
    `<*phi, F_A ^ F_B>` — which share no code and agree to ratio 1.000000000.

  **Scope, asserted by a test:** this is flat R^7 with constant coefficients,
  so the integral is coefficient x volume — a number, **not** a topological
  invariant. It establishes the integrand is non-vanishing, which is what the
  sector needed to exist. Topological content requires a compact G2 manifold.

- **`PM/geometry/exterior_algebra.py`** — sparse differential forms with wedge
  product and a real symbolic exterior derivative. `d^2 = 0` now holds as a
  *structural* zero, verified non-vacuously (`dC_3` has 46 components), with a
  mutation test proving the sign convention is load-bearing. Replaces
  `g2_differential.compute_d_phi()`, which returned `np.zeros(...)`
  unconditionally — so `assert d(d(w)) == 0` passed there while verifying
  nothing.

- **`PM/validation/exterior_degree_gate.py`** — rejects terms whose form
  degrees cannot integrate over their domain. It exists because a proposed
  coupling `int_{13D} C_3 ^ F_A ^ F_B` reached the design stage with degrees
  `3+2+2 = 7` on a 13-manifold. That malformed term ships as the gate's first
  record, **failing**, because a gate whose every record passes demonstrates
  nothing about its ability to reject.

- **`core/physics_config.py`** — a frozen, typed view over `FormulasRegistry`
  with no literal defaults, so action code can read dimensional structure
  without becoming a sixth place those integers can drift. Reads the bulk rank
  dynamically, since `CANON["D_bulk"]` is still `STRUCTURAL_CHALLENGED`.

- **`docs/FUTURE.md`** — CPU-reference -> vectorised -> CUDA roadmap, with the
  governing rule that a second implementation without a parity harness is a
  second source of truth.

### Fixed

- **A missing optional dependency broke the physics.** ~20 modules build
  provenance trees inline in `__init__`, and every EML combinator called
  `require_eml()`, so absent EML killed derivations it was only meant to
  annotate — 33 CI failures including pure-arithmetic tests. Tree builders now
  degrade to an inert node; **evaluators still raise**, because fabricating a
  number would let a missing cross-check pass as a passing one.
- **Two modules used EML as a calculator, not a cross-check.** `baryogenesis`
  read `D_top = exp(-b3/2)` out of the tree via `.tension()`, and
  `strong_cp_axion` called `eml_compute()` for a factor its own comment calls
  provenance. Both now compute in plain arithmetic and cross-check EML when
  present; verified bit-identical beforehand.
- `_can_triple_check` reported a formula as checkable when its only symbolic
  view had no backing package installed, so `triple_assert` raised "no
  symbolic view available". That is a missing extra, not a broken derivation.
- `consistency_beacons.py` used `parents[4]`, which is `src/`, so its
  no-`METAPHYSICA_OUT` fallback wrote reports into `src/AutoGenerated/`.

### Changed

- The reflection-positivity and exterior-degree gates run as **pre-flight**
  build steps, ahead of the simulations, so a structural defect aborts in
  milliseconds rather than after the expensive stages. The RP gate gained the
  `write_report()` it was missing — the reason it had never been wired at all.
- `eml-math` floor raised to `>=2.3.0`, which carries a correctness fix to
  `ln()` below the normal range.

### Known debt, now recorded

- **16,763 lines were never running.** Nine modules are imported under `V19`
  names that do not exist; a systematic rename dropped the suffix and the
  `try/except` guards swallowed every `ImportError`.
  `tests/test_no_silently_dead_imports.py` records them as a ratchet — an
  eleventh dead import fails, and a listed entry that starts resolving also
  fails, so the list cannot rot in either direction. Reviving them is an
  author ruling, not a typo fix: they carry ~1,400 lines of `Formula` literals
  that would enter the paper the moment the imports resolve.

### Tests

- 1271 -> **1337 passing** with EML; 33 failing -> **1027 passing** without it.

## [2.2.0] — 2026-06-13

Unified format-aware ``Get*`` dispatcher (Sprint plan S1-S7).  Every
framework entity — formula, parameter, gate, certificate, paper section,
plot, particle, derivation, reference, simulation — is now retrievable
via a single ``metaphysica.get(name, fmt=...)`` call across eleven output
formats: ``json``, ``yaml``, ``latex``, ``arithma``, ``eml``, ``float``,
``svg``, ``png``, ``pdf``, ``html``, ``md``.

### Added

- **``metaphysica.get(name, fmt=..., kind=..., out_path=...)``** — the
  primary dispatcher (S1).  Resolves *name* through a unified catalog,
  dispatches to the appropriate format backend, and optionally writes
  the result to disk.
- **Typed alias helpers**: ``GetJSON``, ``GetYAML``, ``GetLaTeX``,
  ``GetArithma``, ``GetEML``, ``GetFloat``, ``GetSVG``, ``GetPNG``,
  ``GetPDF``, ``GetHTML``, ``GetMarkdown``.  Each returns the precise
  type for its format (S1-S4).
- **Format constants**: ``metaphysica.JSON``, ``YAML``, ``LATEX``,
  ``ARITHMA``, ``EML``, ``FLOAT``, ``SVG``, ``PNG``, ``PDF``, ``HTML``,
  ``MD`` — ``str``-subclass singletons so ``fmt=metaphysica.PNG`` and
  ``fmt="png"`` are interchangeable.
- **Catalog (``metaphysica._catalog``)**: lazily-built entity index over
  bundled snapshot + build outputs.  Sources ``parameters.json``,
  ``formulas.json``, ``formula_renders.json`` (multi-format sidecar),
  ``GATES_72.json``, ``GATES_CERTIFICATES.json``, ``sections.json``,
  ``plots-manifest.json``, ``references.json``, ``simulations-index.json``,
  bundled quark + constant datasheets, and the derivations cache.
- **Catalog + iteration helpers (S5)**: ``list_all()``, ``list_formulas()``,
  ``list_parameters()``, ``list_gates()``, ``list_certificates()``,
  ``list_sections()``, ``list_plots()``, ``list_derivations()``,
  ``list_references()``, ``list_simulations()``, ``list_particles()``,
  plus per-kind ``iter_*`` generators yielding ``EntityRef`` carriers
  (id + payload + source).
- **Interactive help (S6)**: ``metaphysica.help()`` prints an API
  overview with kind counts; ``metaphysica.help(name)`` shows the
  entity's metadata, supported formats, and example call sites.
- **``metaphysica`` CLI (S6)**: new console script with subcommands
  ``get`` / ``list`` / ``help`` / ``build``.  ``metaphysica get b3
  --fmt latex --out b3.tex`` writes the LaTeX render to disk and exits
  0.  ``metaphysica list`` enumerates the whole catalog per kind.
- **Exception hierarchy (``metaphysica._errors``)**:
  ``MetaphysicaError`` (base), ``MetaphysicaKeyError`` (also a
  ``KeyError``), ``MetaphysicaAmbiguityError``,
  ``MetaphysicaFormatError`` (also a ``ValueError``),
  ``MetaphysicaBackendError`` (also a ``RuntimeError``).  Errors carry
  ``difflib``-based "did you mean" hints.

### Changed

- ``metaphysica.build(out_dir=...)`` now plumbs the build target
  through to the catalog so subsequent ``metaphysica.get()`` calls
  see the freshest outputs without requiring ``METAPHYSICA_OUT`` to
  also be set in the shell.
- Format negotiation is now strict: asking for a format outside the
  per-kind allowed set (e.g.  ``GetPNG('b3')`` — constants have no
  image render) raises ``MetaphysicaFormatError`` listing the
  supported formats.

### Compatibility

- The existing capital-``Get(name, as_json=False)`` API is preserved.
  Quarks and curated constants still resolve via the lower-level
  datasheet builders; new entity kinds (formula, gate, section, ...)
  flow through the new ``get()`` dispatcher.
- New file modules: ``metaphysica/_catalog.py``, ``_get.py``,
  ``_errors.py``, ``_listing.py``, ``_help.py``.  Nothing existing was
  removed.

### Tests

- ``tests/test_get_dispatcher.py``: 43 tests covering every
  (kind × format) pair plus every error-model branch.
- ``tests/test_get_help_cli.py``: 9 tests covering ``help()`` overview
  + entity drill-in plus every CLI subcommand.

## [2.0.0] — 2026-05-14

### Added

- **`_dispatch.py`** — Runtime dispatch layer. `_HAS_RUST: bool` flag and
  `rust_accelerated(fn_name)` decorator provide transparent routing to the Rust extension with
  silent Python fallback when the extension is absent.

- **Rust fast paths wired into the public API:**
  - `Get(name)` — tries `py_get_constant` Rust path for constant lookups first; falls back to
    pure-Python `FormulasRegistry` when the name is not a constant or Rust is unavailable.
  - `list_quarks()` — dispatches to `py_list_quarks` (sorted `Vec<String>` from
    `QuarkRegistry::known_names()`).
