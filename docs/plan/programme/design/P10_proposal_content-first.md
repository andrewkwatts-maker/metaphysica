# P10 proposal: reader levels, content-first

Angle: start from what the reader is told. The primer's ten stops become the topic skeleton; each
topic has one fixed set of slots, written three times (levels 1, 2, 3), and each topic ends at one
named level 4 page. The format, build step, navigation and checks follow from that map.
Brief: `docs/plan/programme/P9_P10_DESIGN_BRIEF.md:51-72`; rules at `:74-78`.

## 1. Content map

### The skeleton every topic shares

Each topic has six slots. Levels change how deep a slot goes. They never change the slot list,
the status label, or the level 4 link.

| Slot | Purpose | L1 public | L2 enthusiast | L3 graduate |
|---|---|---|---|---|
| `hook` | everyday picture ("Picture it") | always | short | optional |
| `claim` | what the model says, in one paragraph | words, whole numbers | words + named physics | standard terms |
| `maths` | the calculation ("The maths") | arithmetic only | algebra, school/undergrad formulas | the actual statement, with indices |
| `status` | label + one line, read from data | same at all levels | same | same |
| `assumption` | what is chosen, not derived | one plain sentence | named | named, with registry key |
| `deeper` | link to level 4 page + next level | "Read more simply / in more depth" | same | + level 4 link in bold |

Rule: `status` and `assumption` are written once, are the same at every level, and come from
data. Only the explanation around them changes from level to level. This stops a simpler level
from making a claim sound more solid than the research level does.

### Worked example: topic 3 `holes` at three depths (outline)

Values in braces are filled from data at build time. Nothing in braces is typed.

**Level 1: "Counting holes"**
- hook: a ball, a doughnut, a pretzel. Stretching a shape never changes how many holes it has.
- claim: the model's 7-dimensional hidden shape was built by Dominic Joyce in 1996. Its holes come
  in two kinds, and the model counts {b2} of one kind and {b3} of the other. These two whole
  numbers are its starting data.
- maths: count a cube's corners, edges and faces: 8 − 12 + 6 = 2 (standard physics, not a
  framework number, so allowed).
- assumption: "The model then says the number of particle families is {b2} divided by 4, which
  gives {n_gen}. Dividing by 4 is a rule the model chose. Nothing forces it."
- status: [Derived] the hole counts; [Ansatz] the families rule.
- deeper: "In more depth (level 2)", "The geometry, research level" (`sections.html#2.4`).

**Level 2**
- hook: one line (the doughnut).
- claim: Euler number χ = 2 − 2g; Betti numbers b1, b2, b3 count holes of each dimension. Joyce:
  start from a 7-torus, fold it by three symmetries, which leaves 12 creases, then smooth them.
- maths: before smoothing b2 = 0 and b3 = 7. Each crease adds 1 to b2 and 3 to b3, so
  b2 = {b2} and b3 = 7 + 3 × {b2} = {b3}. The template writes the 7 and the 3 as text, because
  they are the construction; it writes the results only as `{b2}` and `{b3}`.
- assumption, status, deeper: as level 1, plus a link to level 3.

**Level 3**
- claim: Y7 = resolution of T^7/Γ with Γ ≅ Z2^3. The singular set is {n_creases} copies of T^3.
  Each one is resolved by Eguchi-Hanson × T^3, which adds (1, 3) to (b2, b3). Holonomy wording comes
  from `holonomy_claim` (`geometry_narration.py:116`), which knows when G2 holonomy may not be
  claimed on the path in force.
- maths: b3 = b3(T^7/Γ) + 3·b2, with {on_family} shown as a check (the relation holds or fails on
  the path in force, as `betti_claim` computes at `geometry_narration.py:197`).
- assumption: n_gen = b2/4 is an ansatz. Topic 7 shows the solved action does not produce it.
  The TCS parity obstruction is still open (`docs/claude-context.md:38-39`).
- status: as levels 1 and 2. Registry keys named in small print: `topology.b2`, `particle.b3`,
  `topology.n_gen`.
- deeper: `sections.html#2.4`, `sections.html#4.2`, `paths.html` (the b3 seed is a fork).

If the reader picks a path whose seed gives a different b3, all three levels change together,
because they are filled from the same `fragments(seed)` call (`geometry_narration.py:466`). If
that seed falls off the Joyce family, the level 3 check line shows "fails" and the level 1 and 2
claims carry the falsified/off-family label.

## 2. Source format in the engine

Each topic is one data file plus three short templates, all in the engine:

```
src/metaphysica/reader_levels/
  topics.yaml          # order, id, title, level-4 links, data keys, claims with status
  glossary.yaml        # term -> {l1, l2} definitions
  templates/<topic>/l1.md, l2.md, l3.md    # prose with {placeholders} only
  diagrams/<topic>-<n>.svg                 # inline SVG, classes only, no colours
  status_labels.yaml   # registry status -> reader label (table below)
```

`topics.yaml` record (schema sketch):

```
- id: holes
  title: {l1: "Counting holes", l2: "Counting holes", l3: "Betti numbers of Y7"}
  values: {b2: param:topology.b2, b3: param:particle.b3, n_gen: param:topology.n_gen,
           on_family: narration:betti_claim.on_family}
  claims: [{id: betti, label_from: param:topology.b2},
           {id: families, label: ansatz, text_key: assumption}]
  deeper: ["sections.html#2.4", "sections.html#4.2"]
```

Templates are Markdown with `{key}` placeholders and are filled by the same strict
`format_map` that `geometry_narration.render` uses (`:575-578`): an unknown key fails the build.
Diagrams are separate SVG files that use only the primer's classes (`l-acc`, `f-fg`, `f-acc`,
`f-geo`; `primer_v1.html:95-97`), so the page's `:root` tokens colour them in both themes. A
diagram that shows a framework number takes it as a `{key}` in a `<text>` node, filled like
prose.

Reader labels (the brief's four plus the ones the data needs):

| Reader label | From registry |
|---|---|
| Derived | DERIVED, GEOMETRIC (when the ledger classifies it as not fitted) |
| Fitted | CALIBRATED, ledger FITTED |
| Ansatz | ledger ANSATZ, or a claim marked `ansatz` in `topics.yaml` |
| Falsified | a row in the falsification report, or a ladder check that fails on the path |
| Measured | ESTABLISHED (an input, not a prediction) |
| Not evaluable here | `status: NOT_EVALUABLE` (`canonical_values.py:144`) |

A registry status that has no row in this table fails the build. It is never shown as a guess.

## 3. Generation

- Build step "Write the reader levels", placed after statistics (`build.py:374`) and the ledger
  (`build.py:472`), and before the path ranking (`build.py:467`). It runs
  `python -m metaphysica.generators.generate_reader_levels`.
- Output: `AutoGenerated/reader_levels.json`, one record per topic per level, holding the filled
  prose, the filled SVG, the claims with their labels, the links, and `generated_for_path`.
  It also writes `Pages/levels.html`, a shell copied from `website/`.
- Path choice: no extra mechanism. The file is an AutoGenerated JSON, so a path build writes its
  own copy and `publish.py:43-45` adds it to the path patch. `pm-path-context.js` overlays it when
  the page fetches it. Level pages therefore follow the switcher just as `beginner-guide.json`
  does today.
- NOT_EVALUABLE: the generator replaces the sentence that holds the value. The sentence is marked
  `{value-sentence}` in the template, and the replacement is fixed: "On this path the model cannot
  work this out: {note}." The note comes from the record (`canonical_values.py:147`). The default
  path's value is never shown in its place.
- Falsified on the path: the claim gets a "Falsified on this path" label at every level. Level 1
  adds one fixed sentence: "This part of the model disagrees with measurement on this path."
- No-go path: the opener (topic 0) shows the path's no-go label and reason at all three levels.

## 4. Navigation

The content angle adds this: one URL per topic per level, `levels.html?level=1#holes`, so that a
level 4 page can link down to a specific topic. Every topic ends with "simpler" and "deeper"
links to the same topic one level away. Level 3 also links to level 4. Section 1 lists the level
4 targets, and each one could add a back link in the form "New to this? Level 1 / 2 / 3".
Where the level is stored (URL, then localStorage as in `pm-layperson-toggle.js:45-57`) and the
entry from the home page (`index.html:977`) are left to the navigation proposal. I recommend that
`levels.html` replaces `beginners-guide.html` rather than sitting beside it. The owner decides.

## 5. Checks (each is a test)

1. No literal framework number in a template or SVG. Any digit sequence that matches a value in
   `parameters.json`, `statistics.json` or `action_ladder.json` fails the test. A small allowlist
   in `topics.yaml` holds construction numbers (the 7 and the 3 in topic 3, the cube's 8, 12 and
   6). The test copies the matching approach of `generate_hardcode_audit.py`.
2. Every claim has a reader label, and every label comes from the table in section 2.
3. Status parity: the label of each claim is the same at levels 1, 2 and 3 on the same path.
4. Every level shows the speculative-model statement. It is one data string, which topic 0
   renders at every level.
5. NOT_EVALUABLE: with a fixture where a key is NOT_EVALUABLE, the rendered topic contains the
   fixed sentence and does not contain the default path's value.
6. Links: every `deeper` link points to an existing page. For `sections.html#id`, the id must
   exist in `sections.json`.
7. Reading level, without a library: average sentence length of at most 16 / 22 / 30 words for
   L1 / L2 / L3; no TeX in L1; every glossary term used in L1 has an L1 definition; L1 avoids a
   list of jargon words unless the word is defined in the glossary.
8. `forbidden_phrases()` (`geometry_narration.py:581`) finds no match in any rendered level on
   the path in force.
