# P9 proposal, angle "incremental": the cost of N paths (2026-11-11)

Thesis: a path is the main build plus a small difference, and the build already proves it. The
site publishes paths as RFC 6902 patches against main (`testground/results/publish.py:90-113`),
and 12 of the 37 published deviations change no result file at all. A sweep should therefore run
only the steps a path can change, keep everything else shared with main, and after a fix wave rerun
only the steps whose code, inputs or fork reads the fix touched. Today each path is a full fast
build, run one at a time.

**Key cross-check.** I compared the 2026-11-01 fork reads with the 2026-10-27 path index. Every
deviation of a fork that no process read is inert: 12 of 12 (`b3_origin` ×4, `bulk_signature` ×2,
`face_genericity`, `joyce_contribution_table`, `metric_construction`, `moduli_indexing` ×2,
`twisted_norm_convention`). So on real data, "no process reads it" predicts "nothing changes". The
two inputs come from different builds, so this supports the rule but does not prove it.

**Findings this design depends on:**
- (F1) The reads are kept per process, not per step. `begin_fork_reads` points every step at one
  directory (`build.py:664-676`), and a file holds only `{"reads", "closed_gate_reads"}`
  (`variants/selection.py:245-257`). A read cannot be traced back to the step that made it.
- (F2) In-process steps lose their reads. "Export the path graph" runs inside the orchestrator
  (`build.py:554-557`). The orchestrator writes its own reads file at exit, after
  `merge_fork_reads` (`build.py:726`, the atexit hook at `selection.py:260-264`). That explains the
  48 files against 47 processes.
- (F3) Path runs are serial. PM declares `shared_state=True` (`theories/pm/__init__.py:219`) and
  `check_jobs` refuses `--jobs > 1` (`testground/sweep/execute.py:31-39`). The cause is the legacy
  `AutoGenerated` junction (`simulations/__init__.py:124`).
- (F4) The run cache is all-or-nothing per path. It is keyed by (theory, digest, engine fingerprint)
  (`runner/cache.py:3`), the fingerprint hashes every `*.py` in the engine (`runner/fingerprint.py:4`),
  and the digest covers the whole selection (`configurations/model.py:47-53`). So any code change,
  or a new fork, misses on every path.
- (F5) The site falls back to main. When a patch's base sha256 does not match, the page shows main
  with the notice "results unavailable for this file: showing main" (`website/js/pm-path-context.js:16`,
  `:102`). That borrows from the default path, which the brief forbids, and a cheap incremental
  rebuild of main would trigger it more often.

## 1. Path identity

- id: keep `<fork>--<option>` (`publish.py:26`) for one departure. For a combination, join the
  departures sorted by fork id with `+`: `dark_energy_betti--b2_4+h0_route--kk_bridge`. Only
  departures appear in the id, so a new fork, which defaults to no departure, changes no existing id.
- Cache key (the angle's addition): hash the departures only, restricted to the forks a step read.
  It does not use `digest_of` over the full selection (F4).
- Which paths are built: every single departure, because 32% of them cost nothing here (section 3),
  plus the owner's named combinations and candidates. The owner decides, through the selection list
  that `sweep/selections.py` already reads. Beyond this the angle has nothing to add.

## 2. Layout

- Keep the existing layout: `AutoGenerated/paths/index.json` (`metaphysica.paths/1`, written at
  `publish.py:294-318`) and `paths/<id>/{patch.json, summary.json}`. Main stays in `AutoGenerated/`.
  Sharing comes from that layout: a file a path does not change is not stored for it. A page
  overlays the patch on main's file (`pm-path-context.js:4-8`).
- Add to each index entry (schema `metaphysica.paths/2`):
  `{"built_commit": "<sha>", "base_commit": "<sha>", "stale": bool, "steps_rerun": int,
  "steps_shared": int, "plots_not_evaluable": ["plots/<name>", ...]}`. A path is `stale` when main's
  file hash has moved and its patch was not recomputed. The site then shows NOT_EVALUABLE with
  "out of date since <commit>", never main (replacing F5).
- Shared and never per path: `images/`, `css/`, `js/` and the templates. Plots (3.2 MB) are shared
  only where the path does not change their inputs (section 5).
- Offline only, never published: `.runs/steps/<step_id>/<trace_key>.json` (the trace) and
  `.runs/blobs/<sha256>` (the output files, stored once by content). A path's run root is put
  together by hard-linking blobs, which is a cheap operation on one NTFS volume.
- Size: measured 223 KB mean per path, so 30 paths come to about 6.7 MB and 100 to about 22 MB
  (assumption: the mix of paths stays as measured). Main's base hash appears in every patch, so a
  change to a main file rewrites every patch that touches that file. Git growth per publish is
  bounded by the total of the patches. PDFs: 944 KB each, for main and named candidates only.

## 3. Build

### Which steps depend on the path: a verifying trace per step

A step is rerun for a path only if its recorded trace no longer holds there. The trace of one step
execution records:
- `code`: a hash of the engine modules the step's processes imported (from `sys.modules`) and of any
  package data files they opened;
- `inputs`: each file read under the out dir, with its masked hash (volatile keys masked as in
  `publish.py:72-87`);
- `forks`: each fork it resolved, open or behind a closed gate, with the option seen (`selection.py:222-229`);
- `outputs`: each file written, with its blob hash.

**Lookup.** For each step, in `STEPS` order, find a trace with the same `code`. The trace holds when
the current selection gives the same option for every fork in `forks`, and the current files match
`inputs`. Then link the step's outputs from the blob store and do not run it. Otherwise run the step
and store a new trace. Main and every path share one store, so for most steps on most paths the
step reuses main's trace: that is the sharing. The rule is sound when a step is deterministic up to
the volatile masks and reads its options only through `resolve`. The tests in section 6 check both
conditions.

**Early cutoff.** When a rerun step writes outputs whose masked hashes equal main's, the steps
downstream still find their `inputs` unchanged and are not rerun.

**Recording**, a sketch of about ten lines (owned by `src/metaphysica/buildtrace.py`):

```
# installed by variants' existing per-process hook (selection.py:260), set when METAPHYSICA_TRACE_DIR is
def _audit(event, args):
    if event == "open" and _under(args[0], OUT, ENGINE):
        (WRITES if _writes(args[1]) else READS).add(_rel(args[0]))
sys.addaudithook(_audit)
atexit.register(lambda: _dump(step_dir, READS, WRITES, _imported_engine_files(), reads(),
                              closed_gate_reads()))
```

`_execute` (`build.py:699`) points `METAPHYSICA_FORK_READS_DIR` and the trace directory at
`fork_reads/<step_id>/` for each step, using the existing `_step_id` (`build.py:504`). This fixes F1.
In-process steps write their trace before `merge_fork_reads` runs, which fixes F2. All 48 processes
import variants, which is why the hook goes there. A step whose top process does not import variants
is wrapped with `python -m metaphysica.buildtrace <cmd>`.

### Cost model (measured inputs; anything marked A is assumed)

The 37 measured deviations fall into three classes:
- **Class 0 (12/37):** the fork is read by no step. No step reruns; only the patch is written,
  about 5 s (A).
- **Class B (4/37):** the fork is `b3_seed` or `chi_eff_route`, which every process reads at start.
  Every step reruns, about 400 s. Early cutoff saves nothing because every step reads the fork.
  Splitting these start-up reads out by value is out of scope.
- **Class C (21/37):** the fork is read by 1 to 7 processes. "Run all simulations" reads 16 forks,
  so it nearly always reruns (124 to 148 s). The steps after it rerun only where their inputs
  changed. I assume about 250 s for an average path (A), with 140 s as the lower bound and 400 s as
  the upper.

Mean per path (A): 0.32 × 5 + 0.11 × 400 + 0.57 × 250, which is about 190 s, against 400 s today.
With a cache per simulation inside `run_all_simulations` (step 6 below), I assume Class C falls to
about 150 s and the mean to about 130 s (A).

| Paths | Today (serial, 400 s each) | Step traces, serial | Plus parallel (6 workers, A) | Plus a cache per simulation, 6 workers (A) |
|---|---|---|---|---|
| 30 | 3.3 h | 1.6 h | 16 min | 11 min |
| 100 | 11.1 h | 5.3 h | 53 min | 36 min |

Parallel work needs the shared state removed (F3). That is step 3. I assume 6 workers on 24 cores
because I did not measure memory. Named combinations depart more forks and sit higher in the range.

**A fix wave.** Only steps whose `code` hash changed are rerun, on main and on every path where that
step's trace no longer holds. Measured step times give the scale:
- a fix to a generator under 1 s costs about 1 s × (N + 1);
- a fix to a simulation costs about 140 s × (N + 1) / workers;
- a fix to a module that every process imports, such as the registry, rebuilds everything. That is
  the honest worst case.

**Twins.** The volatile masks need a second main build (`publish.py:72-75`). It is never taken from
the cache: one twin per engine commit.

### Failures and CI

- **Failures.** A failing step on a path is recorded in that run root's `build_status.json`
  (`build.py:527-535`, with `--keep-going` as PM already passes it at `theories/pm/__init__.py:94-95`).
  It reaches `summary.failed_steps` (`publish.py:205`), and its outputs are never stored as a trace.
  The steps that needed those outputs fail their lookup and run against the missing file, so the
  values they cannot derive become NOT_EVALUABLE on that path. They are never filled from main. Other
  paths continue: the pool already records NOT_RUNNABLE per configuration (`runner/worker.py:14`).
- **CI.** Today `ci.yml:57-58` runs one fast build on each of 3 legs (`ci.yml:13-14`); the run takes
  about 1 h 24 min in all. Proposal: the 3.12 leg only restores `.runs/` from the Actions cache,
  keyed by the parent commit. The parent commit's traces are then on hand, so a commit costs only
  what it touched. The leg reruns invalid traces for all published paths within a 30-minute budget.
  Paths it does not reach are published as `stale` (section 2). It never borrows main.
- **Offline.** Full sweeps of new combinations, the twin, PDFs and per-path plots for candidates,
  and the equivalence audit (test T1). Store size (A): main is 43 MB, plus about 22 MB of changed
  outputs for 100 paths after deduplication by content. That fits the 10 GB Actions cache limit.

## 4. Evaluation

- Records: keep `summary.json` (keys measured: `scoreboard`, `chi2`, `gates`, `certificate`,
  `changed`, `inert`, `failed_steps`). The angle adds `steps_rerun` and `steps_shared`, so a reader
  sees how much of a path really ran.
- Paths that score fewer rows: compare chi2 only over the rows both paths score. `rank.py:67-73`
  sorts by consistency, ladder, gates and then chi2, and `missing` is already reported
  (`rank.py:99`). The angle has nothing to add here.
- Rank change after a fix wave: a path's rank can move only if one of its step traces was rerun.
  Each finding therefore names the cause: the commit, the steps whose `code` hash changed, and the
  rows that moved. A path with no rerun step and a new rank is a ranking bug, which T8 checks.
- No-go label and reason: unchanged, taken from the variants status. The angle has nothing to add.

## 5. Site

- Switcher, `?path=` in the URL and sessionStorage: already exist (`pm-path-context.js:4-8`).
  The angle has nothing to add.
- What changes is the fallback. A stale entry or a sha mismatch now shows NOT_EVALUABLE with the
  reason (main moved, or path out of date since <commit>) and never main's value (F5).
- Plots: the probe records each plot's input files. A shared plot whose inputs appear in a path's
  patch is listed in `plots_not_evaluable`. The page then shows a placeholder: "plot not drawn for
  this path". It does not show the main plot.
- Paper per path: `sections.json` and `core_paper.json` are already patched on 21 and 10 paths.
  PDFs (944 KB, an extra step) are built offline for main and named candidates only.

## 6. Tests (one per rule that can be broken)

| # | Rule | Test |
|---|---|---|
| T1 | A path built from traces equals the same path built in full | slow and offline: two paths of different classes, masked hash per file equal |
| T2 | A step's fork reads land in its own directory | fake two-step build; `fork_reads/<step_id>/` holds the right counts; in-process steps are counted (F2) |
| T3 | No option is read except through `resolve` | static: no `METAPHYSICA_VARIANT_` or `METAPHYSICA_SELECTION` lookup outside `variants/` |
| T4 | A step writes only under its run root | the probe flags a write outside it; two paths built in parallel equal the serial build (F3) |
| T5 | A trace misses when its code, inputs or a read option changes | unit test with a fake step and a fake store, one case each |
| T6 | Early cutoff: an unchanged masked output stops the rerun | fake chain A→B; A reruns with the same bytes, B does not |
| T7 | A stale or mismatched patch shows NOT_EVALUABLE, never main | `tests/js/path_context.test.mjs` case |
| T8 | A rank change has a cause | rank diff with a moved path and no rerun step fails |
| T9 | A plot with changed inputs is not shown on the path | `plots_not_evaluable` fixture and page check |
| T10 | A failed step on one path does not stop the others and is never cached | fake runner fails path 2 of 3; path 3 publishes; no trace for the failed step |

## 7. Order of work (lane-sized, each with owned files and an acceptance test)

1. **Per-step reads and true timings.**
   Owns: `build.py` (`_execute`, `_tolerated`, `merge_fork_reads`).
   Gives `fork_reads.json` a `by_step` map; logs the real elapsed time when exit 72 is tolerated;
   in-process reads are kept.
   Accept: T2, and a fast build whose summary shows a non-zero time for simulations.
2. **The trace probe.**
   Owns: new `buildtrace.py`, plus the hook line in `variants/selection.py:260`.
   Accept: T4 (first half), and a trace for each of the 62 fast steps on one real build. The
   step-to-fork table that build gives replaces the class split in section 3, which was estimated
   from per-process files.
3. **Remove the shared state.**
   Owns: `simulations/__init__.py:124` junction use, `theories/pm/__init__.py:219`.
   Accept: T4 (second half), with `--jobs 4` allowed for PM.
4. **Step store with verifying traces.**
   Owns: new `testground/runner/stepcache.py`, and `build.py` (`_execute` asks the store).
   Accept: T5 and T6. A second main build with no change reruns 0 steps.
5. **Sweep on the step store.**
   Owns: `runner/worker.py`, `sweep/execute.py`, the departures-only key and `+` ids
   (`publish.py:26`).
   Accept: T1 and T10. A class-0 path reruns 0 steps; publish records `steps_rerun`.
6. **Cache per simulation inside the simulations step.**
   Owns: `simulations/run_all_simulations.py`.
   Accept: a class-C path reruns only the simulations that read its fork. The measured time is
   recorded and replaces assumption A.
7. **Index v2 and site with no fallback.**
   Owns: `publish.py` (`_write_index`), `pm-path-context.js`.
   Accept: T7 and T9.
8. **Rank change findings.**
   Owns: `generators/generate_path_ranking.py`, `testground/rank.py`.
   Accept: T8. Rerun the ranking from the stale `path_ranking_137dd42.json`, and every moved path
   names its steps.
9. **CI leg.**
   Owns: `.github/workflows/ci.yml`.
   Accept: a commit that touches one generator reruns only that step across all paths, inside the
   30-minute budget, with the remainder marked `stale`.

**Assumptions to replace by measurement (step 2 and step 6 measure them):**
- the class split comes from per-process reads of a 2026-11-01 build, set against a path index of
  2026-10-27;
- the 250 s and 150 s Class C costs;
- 6 parallel workers;
- the 5 s publish-only cost;
- that store size scales with patch size.
