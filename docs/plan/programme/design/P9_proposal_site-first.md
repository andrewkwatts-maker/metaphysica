# P9 proposal, angle "site-first" (2026-11-11)

Start from the reader. On any page they pick a path. Every value, formula, paper section and
parameter then comes from that path. A no-go path is marked as no-go on every page. A value
the path cannot give reads "not evaluable on this path" and never shows the main value.
The layout, the index and the loader below all follow from those four promises.

## 0. What already exists (the site half of P9 is built, and broken by staleness)

- Loader: `website/js/pm-path-context.js`. It is the first script on every page:
  `index.html:13` and `Pages/paper.html:10`. Grep measured that all 20 `Pages/*.html` include it.
  The loader keeps the choice as `?path=` first, then sessionStorage `pm.path`, then main
  (`:4`, `:85-94`, `:130-137`). It wraps `fetch` (`:213-220`) and applies an RFC 6902 patch to
  any `AutoGenerated/*.json` (`:171-179`, `:195-211`). The base file must match a sha256
  (`:100-108`). It shows a bar off main and a "Main path" chip on main (`:253-303`), and it
  keeps `?path=` on internal links (`:313-325`).
- Publisher: `testground/results/publish.py` (`paths-publish`, `testground/cli.py:1148`). It
  writes `paths/index.json` (schema `metaphysica.paths/1`, `:312-316`) and
  `paths/<id>/{summary,patch}.json` (`:256-260`). Paths whose required step failed go to
  `not_computed`, with a reason (`:280-287`). Index entry fields come from
  `theories/pm/results.py:194-213`.
- Paths page: `js/pm-paths-page.js:6` reads `path_graph.json`, `paths/index.json` and
  `paths/<id>/summary.json`.
- Paper text: `{{param:key}}` is replaced on the client (`js/pm-paper-param-processor.js:10`),
  so a patched `parameters.json` reaches the paper prose.

Problems seen from the reader's chair. I measured each one; none of them is an assumption.
- **P-a (borrowed values, live today).** On the sha mismatch the overlay returns the main
  file (`pm-path-context.js:207`). The site tree has 57 patched base files and 38 of them no
  longer match `paths/index.json`. Five of the mismatches are `parameters`, `formulas`,
  `sections`, `theory_output` and `core_paper` (sha256 measured). The index was generated
  2026-10-26 at engine `c294094`, and `parameters.json` was last committed on 2026-11-01. So
  every path now shows main's numbers on every page, under a one-line notice (`:16`, `:289-294`).
- **P-b (borrowed values, latent).** A file that is missing from a path build is skipped
  (`publish.py:96-97`), and a file that cannot be verified is left out of the patch
  (`:109-110`). Either way the loader serves main for that file (`pm-path-context.js:201`).
- **P-c.** Fast builds skip plots and the PDF (`build.py:38`, `:629`). Plot images are not
  fetched through `fetch`, so a path shows main's plots.
- **P-d.** An unknown or removed `?path=` falls back to main with no message
  (`pm-path-context.js:337-339`).
- **P-e.** A no-go path shows only the raw word `(disabled)` in the bar (`:259-264`).
- **P-f.** A null value renders as `?` (`pm-constants-loader.js:1065`). At least six separate
  formatters exist: `pm-constants-loader.js:1064`, `pm-paper-renderer.js:2077`,
  `pm-tooltip-system.js:105`, `pm-paper-tooltips.js:780`, `pm-certificates.js:202` and
  `pm-geometry-to-physics.js:18`. Grep found number formatting in 20 JS files.
- **P-g.** There are three id schemes: `fork--option` (`publish.py:26`), 12-hex `selection_id`
  (`variants/selection.py:125-131`, which returns `"active"` for the default) and 16-hex
  `digest_of` (`testground/configurations/model.py:47-54`, used by `path_ranking.json`
  rows). On top of that, `enumerate_runs` rejects any id without `--` (`publish.py:155`), so
  a named combination cannot be published.

Measured and assumed figures are listed in section 8.

## 1. Path identity

The reader sees the id in the URL and shares it. It has to be readable, short and safe in
`ID_RE` (`pm-path-context.js:14`).

| Kind | id | Example |
|---|---|---|
| default | `main` (alias `active`, `selection.py:129`) | `main` |
| one departure | `<fork>--<option>` (as today) | `b3_seed--seed_24` |
| owner-named combination | `c_<slug>` | `c_seed24_thawing` |
| unnamed combination (sweep) | `x_<selection_id>` (12 hex) | `x_9d35e2f8fbd9` |

- The id is built from **departures only**, after `canonical_departures`
  (`selection.py:120-122`) has dropped forks behind a closed gate. Adding a fork leaves every
  id unchanged, provided the new fork's default is its `legacy_option` (`model.py:185-187`).
  A test checks that proviso (T9).
- An id names a selection, not a result. Every index entry stores the full `selection` (it
  does so today, see measured entry) and the `engine` commit. If the adopted default moves,
  `b3_seed--seed_24` still means "seed_24, everything else at the default of this build". The
  switcher shows the departures, so the reader never has to decode the id.
- `path_ranking.json` joins by `selection`, not by its 16-hex id. The ranking emits the
  index id beside its own (step S1).
- **Which paths are built.**
  - Every single departure, using `option_ids()` and **not** `sweepable_ids()`, because the
    latter drops DISABLED options (`switches/model.py:243-246`). The owner's rule is that
    no-go options still run. Measured: 26 forks, 50 single departures (39 considered,
    11 disabled), 0 unimplemented, 2 gated forks.
  - Owner-named combinations and candidates, listed in one committed file
    (`data/paths/named.json`: `{slug: {fork: option}}`, checked by `load_selection`,
    `selection.py:134-147`). **The owner decides** by editing that file.
  - The top-k unnamed combinations from the last `testground rank`, chosen by the planner per
    wave.
  - An incompatible selection (`compatible`, `selection.py:103-105`) is listed but not built,
    with the violation as its reason.

## 2. Layout

The reader's page fetches `AutoGenerated/<file>.json`, and the loader turns that into the
chosen path's file. Per-path full copies would cost about 43 MB each (the `AutoGenerated/`
size measured), or 4.3 GB for 100 paths. That is far over what a static Pages site carries.
So **keep patches.** The published average is 219 KB per path (measured).

```
AutoGenerated/                  main path, unchanged
AutoGenerated/paths/index.json  metaphysica.paths/2 (below)
AutoGenerated/paths/<id>/summary.json   evaluation record (section 4)
AutoGenerated/paths/<id>/patch.json     metaphysica.path_patch/2
AutoGenerated/paths/<id>/files/...      own binaries: plots, PDF (candidates only)
```

What is shared: everything outside `AutoGenerated/` (templates, css, js, images), plus every
JSON file that a path lists as `same`.

`path_patch/2` changes the default from "not in patch means main" to "not listed means
withheld". That one change closes P-a and P-b:
```
{"schema":"metaphysica.path_patch/2","path":"<id>","main_build":"<sha of main parameters.json>",
 "files":{"<name>":{"base_sha256":..,"ops":[..]}},      // changed, verified
 "same":{"<name>":"<base_sha256>"},                      // built on the path, identical to main
 "withheld":{"<name>":"missing on path | unverified | volatile"},
 "assets":{"plots/x.png":"paths/<id>/files/plots/x.png" | null}}  // null = not built here
```
`index.json` (`metaphysica.paths/2`) is what the switcher needs and nothing more. Details stay
in `summary.json`.
```
{"schema":"metaphysica.paths/2","main_build":"<sha>","engine":{..},"generated":"..",
 "paths":[{"id","kind":"main|single|named|combo","label","departures":{..},"selection":{..},
   "status":"active|considered|disabled","nogo":{"is":bool,"reasons":[".."]},
   "rank","rank_prev","rows_scored","rows_total","not_evaluable","inert","has_pdf"}],
 "not_computed":[{"id","departures","reason"}]}
```
`main_build` ties the index to one main build. The site check T4 refuses a site tree where
any `base_sha256` or `same` sha differs from the file it sits beside.

**Size budget.** Assuming size grows linearly from the measured 219 KB average (max
1.86 MB, `b3_seed--seed_24`):
- 50 single departures: about 11 MB.
- 100 paths: about 22 MB.
- PDF for main plus at most 5 candidates (944 KB each): about 5 MB.
- Plots for candidates (3.2 MB each): about 16 MB.
- Total at 100 paths: about 43 MB beside the 43 MB main tree.

Git history grows by the changed patch bytes on every republish. That is an assumption, since
I have not measured gzip size or deltas.

## 3. Build

From this angle the site needs exactly one thing from the build: **the main tree, every
patch and the index all come from one main build and are copied into the site in one
commit.** Everything else here is for the lanes that own the pipeline.

- Path-dependent steps. `fork_reads.json` counts reads per process (pid-named files,
  `build.py:664-696`), not per step. That means it cannot yet say which steps depend on a
  path. A per-step attribution is needed: the `_run` step label goes into the reads file
  name. That belongs to the pipeline proposal; this angle adds nothing beyond it.
- Failures of one path stay where they are today: `not_computed` with a reason
  (`publish.py:280-287`), plus `failed_steps` per entry (`:262`). The switcher shows them
  greyed out, with the reason as a tooltip.
- Wall clock. The published sweep measured 37 path builds at 166 to 241 s each (median 181,
  total 6736 s) on engine `c294094`. The brief gives about 400 s for a fast build today.
  Assuming 400 s each with no contention:
  - 30 paths: 3.3 h serial, about 0.8 h on 4 workers.
  - 100 paths: 11.1 h serial, about 2.8 h on 4 workers.
- CI: no sweep. `.github/workflows/` holds only wheels, PyPI and tests (`workflow.yml:1`),
  and the site repository has no workflows (measured). CI runs the cheap checks T4 to T8 on
  fixtures. The sweep, `paths-publish` and the site copy run offline on the owner's machine.

## 4. Evaluation, as the reader sees it

Each switcher entry shows: rank, "scored on n of N rows", chi2/dof, ladder failed/total, the
not-evaluable count and a no-go badge. The paths page shows the full `summary.json`. The
measured summary keys today are `certificate`, `chi2`, `gates`, `scoreboard`, `key_values`
and `n_gen`. Add:
`{for:[..], against:[..], alignment:{chi2,dof,rows_scored,rows_total}, ladder:{failed,total},
not_evaluable:[{id,note}], nogo:{is,reasons}, rank, rank_prev, rank_commit_prev}`.
- chi2 is computed over the row set that every computed path scores. Rows that are not
  evaluable on a path are listed, never filled with values.
- A path that scores fewer rows shows that number next to its rank. The ordering rule belongs
  to `testground rank` (`path_ranking.json` `rule`); this angle only requires the count to be
  shown.
- No-go status is computed at publish, never in JS. A path is no-go when any departure is
  DISABLED, and the reasons are the option's `consequence`, `kill_condition` and
  `decision_refs` (`switches/model.py:100-105`). It is also no-go when any named
  `kill_condition` fires. A no-go path is still built, scored and ranked. It keeps its label
  however well it scores.
- Re-run after a fix wave: `rank_prev` comes from the previous index. Any entry whose rank or
  no-go verdict moves becomes a row in `paths/changes.json`
  (`{id, rank_prev, rank, commit_prev, commit, why}`), shown at the top of the paths page as
  findings.

## 5. Site

- **Switcher.** It goes in the header on every page, in `createHeaderHTML`
  (`js/pm-header.js:117`) next to the nav row (`:158`). It is a native `<select>` with
  optgroups, so it works on a phone and from the keyboard:
  - Main
  - Owner candidates
  - Single changes, grouped by fork question
  - No-go (still run), collapsed
  - Not computed (disabled options, each with its reason)

  It reads `PMPath.index()` (`pm-path-context.js:353`) and calls `PMPath.select`
  (`:231-235`).
- **The choice in the URL.** `?path=` is the authority. sessionStorage carries it within a
  tab, and links keep it (all as today). An unknown id shows "Path X is not in this build;
  showing main" in the bar, instead of the silent fallback (P-d).
- **Loading.** Keep the fetch overlay. Each file falls under one rule:

  | File is listed under | The loader |
  |---|---|
  | `files` | Checks the sha, then patches. |
  | `same` | Checks the sha, then serves the main file. |
  | anything else | Serves nothing (withholds the file). |

  "Serves nothing" means the loader answers with status 424 and the body
  `{"withheld": reason}`. Loaders then take their error state (`js/pm-loading-states.js`),
  and the bar lists the withheld files as "not built for this path". It never returns main
  on a sha mismatch (P-a). The sha check also applies to `same`.
- **Plots and PDF.** `plots-manifest.json` is patched. An image path is rewritten to
  `paths/<id>/files/...`, or carries `"not_built_on_path": true`, in which case
  `pm-plots-loader.js:16` draws a placeholder rather than main's PNG (P-c).
- **Not evaluable.** Add one helper, `PMPath.display(value, record)`. It returns
  "not evaluable on this path", with the record's `note` as a tooltip, whenever
  `status == "NOT_EVALUABLE"` or the value is null on a non-main path. The six formatters in
  P-f delegate null and status handling to it, so no page prints `?`, `0`, `NaN` or `null`.
  The paper's `{{param:key}}` and formula values go through the same helper.
  - Engine requirement for L9: on a path, a value that cannot be derived is written as the
    `canonical_values.py:140-150` shape: `value: null`, `status: NOT_EVALUABLE` and a `note`.
  - Today no `parameters.json` entry uses that shape: 0 of 816 entries, and no null values
    (measured).
- **No-go on every page.** `mountUi` (`pm-path-context.js:296-303`) runs on every page. When
  `nogo.is` is set, the bar turns red with `data-nogo` and reads: "No-go path: <first
  reason>. It is still run and checked. Nothing here is a prediction." It links to
  `paths.html#<id>`, and the bar also prints (`@media print`).
- **Paper per path.**
  - Every path gets its paper HTML, through the patched `sections.json`, `core_paper.json`
    and `{{param:key}}`.
  - A PDF is built for main and for owner candidates only (`has_pdf`), into
    `paths/<id>/files/`.
  - No page links the PDF today (grep over `Pages`, `js` and `index.html` found nothing). The
    paper page gains a PDF link only when `has_pdf` is set. Otherwise it reads "No PDF for
    this path; print this page".
