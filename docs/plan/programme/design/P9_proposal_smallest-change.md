# P9 proposal: smallest change (a build per path, a site that switches paths)

Angle: reuse what exists and add as few new parts as possible. Read-only survey, 2026-11-11, branch
`site-review`. Paths are relative to `src/metaphysica/` unless they start with `docs/`,
`tests/`, `.github/` or `PrincipiaMetaphysica/`.

## Verdict

Most of P9 already exists. Two parts are built and do not connect, and three rules are broken:

1. A build per path exists. The sweep runs a fast `--keep-going` build of every selection, each in
   its own root, and resumes when it is run again.
2. A site that switches paths exists. Every page overlays each `AutoGenerated/*.json` fetch with
   that path's RFC 6902 patch and keeps the choice in `?path=`.
3. The broken link: the in-repo sweep writes `<runs>/pm/<fingerprint>/<digest>/`, but
   `paths-publish` reads `<runs>/<fork>--<option>/DONE.json`. Only a script outside the repo
   writes that layout. The rank uses a third id, the digest.
4. Three rules are broken: the site borrows main's values; the no-go label is shown only as a
   status word; chi2 is not computed over a common set of rows.

This proposal fixes the link and the rules. It adds no new subsystem.

## Assumed

A fast build takes about 400 s per path today (the brief's figure; the 181 s median is from
October and the build has grown since). Scaling is linear in paths and `--jobs` (CPU and RAM
headroom not measured). A combination's patch is no larger than the sum of its singles'. GitHub
Pages limits a site to about 1 GB.

## 1. Path identity

- **Singles keep the id that is already published:** `<fork>--<option>` (`publish.py:26`,
  `pm-path-context.js:14`). It is readable and stable. A new fork does not change it, because
  departures leave out default options (`selection.py:108-117`).
- **Named combinations** use a short owner-given name that matches `[A-Za-z0-9_]+` with no `--`.
  Both regexes already accept this form. Only `enumerate_runs` refuses it (`publish.py:155`).
- **Every index entry also carries `selection_id`** (`selection.py:125`) and `departures`, the
  stable key. The publisher refuses a name whose `selection_id` changed since the previous index;
  a single whose option became the default leaves the index and is reported as `retired`.
- **Not used as public ids:** the configuration digest (`configurations/model.py:47`), because
  adding a fork changes it, and the `fork=opt` label, because `=` and `,` fail the URL regex.
  Both stay internal to the testground.
- **Which paths are built:** all singles, every status, DISABLED included (the owner's rule, in
  the programme file), plus the named paths in one owner-edited file,
  `theories/pm/named_paths.json` (`{name: {fork: option}}`, checked with `load_selection`,
  `selection.py:134-147`).
- **Who decides:** the owner adds names. An agent may propose one in a commit that records the
  decision in DECISION_LOG.
- **Joint and sampled runs** (`commands.py:46-49`) stay audit evidence only, with no public id.

## 2. Layout

Keep the layout that is already published. The default path stays where it is.

```
AutoGenerated/                    main path (unchanged)
AutoGenerated/paths/index.json    metaphysica.paths/1 (publish.py:312) + additive fields below
AutoGenerated/paths/<id>/patch.json    RFC 6902 ops per file, base_sha256 per file
AutoGenerated/paths/<id>/summary.json  metaphysica.path_summary/1 (results.py:172)
AutoGenerated/paths/<id>/paper.pdf     named paths only, optional (section 5)
```

**Shared across paths:** every non-JSON file (HTML, JS, CSS, images, plots, the main PDF).
**Path-specific:** every JSON file under `AutoGenerated/`, through its patch.

These fields are added to each `paths[]` entry, so the schema stays `/1` as long as
`PrincipiaMetaphysica/docs/plan/paths/contracts.md` allows extra keys (L9 checks this first):

```json
{"selection_id": "3fa9…", "departures": {"b3_seed": "seed_24"},
 "no_go": {"label": "no-go", "reason": "<kill_condition or consequence>", "certainty": "certain"},
 "n_not_evaluable": 4, "rank": 7, "rank_previous": 5}
```

Top-level additions: `"previous": {"generated", "engine"}`, `"retired": [ids]` and
`"findings": [...]` (section 4).

**Size budget:** measured 8.6 MB for 37 paths, a mean of 0.23 MB per path. The estimate for
100 paths is about 25 MB per publish (assumed distribution). Full copies would be 43 MB × 100 =
4.3 GB, past the Pages limit, so patches are the only layout that fits. Each publish rewrites
the patches, so the site repository's git history grows by roughly the patch size per publish
(assumed).

## 3. Build

- **Which steps depend on the path.**
  - The fork-read files have no step tag (`selection.py:253`). The smallest fix:
    - `_run` sets `METAPHYSICA_BUILD_STEP=<_step_id>` (`build.py:574`);
    - `write_reads` puts it in the file name;
    - `merge_fork_reads` adds a `by_step` map to `fork_reads.json`.
  - The map is evidence only. Steps read each other's `AutoGenerated` outputs and that data flow
    is not tracked, so a step that reads no fork can still render values that differ by path.
  - This proposal skips no steps. Every path runs a full fast build, which already leaves out
    the extras such as the PDF (`build.py:629-630`).
  - The patch does the deduplication: unchanged values cost nothing to store.
- **How a sweep avoids rebuilding.** The run cache already does this. A path is rerun only when
  the engine fingerprint changes (`execute.py:3-5`), so `sweep --singles` after a partial run
  resumes where it stopped.
- **Where one path's failure is recorded.** This already works at three levels: the step
  (`build_status.json`, `build.py:527`), the run (`run_log.json`, NOT_RUNNABLE with a reason,
  `worker.py:11-15`) and the publish (`not_computed` with a reason, `publish.py:284-287`). The
  sweep carries on to the next path (`commands.py:124-133`).
- **The missing link (G1).** In place of the scratch driver, `enumerate_runs` (`publish.py:149-159`) gains a second reader for
  a sweep fingerprint directory. It reuses the rank's `_finished` check (`rank.py:183-193`):
  the selection comes from the stamp, `exit` and `secs` from `run_log.json`, and the id from one
  shared function, `path_id(selection, named)`, placed next to `label` in `sweep/selections.py`.
  `rank.load_entries` (`rank.py:206`) uses the same function in place of `root.name`. After this
  change, `rebuild_all.sh` and the scratch `sweep.py` are no longer needed.
- **Twin build.** The cache would reuse the default run, so the twin goes in a second `--runs-dir`.
- **Wall-clock cost, serial (`--jobs 1`), with the default run and the twin:** 30 paths take
  (30+2)×400 s ≈ 3.6 h at the assumed 400 s, or ≈ 1.6 h at the October median of 181 s; 100
  paths take ≈ 11.3 h, or ≈ 5.1 h. The full main build for the site comes on top (not measured).
- **Parallel runs (G6), the one change with a real time gain.**
  - Move the six legacy writers listed above onto `METAPHYSICA_OUT`.
  - Then delete the junction (`simulations/__init__.py:131`) and set `shared_state=False`
    (`theories/pm/__init__.py:219`).
  - `--jobs 4` would then bring 100 paths at 400 s to about 2.8 h (assumed linear scaling and 4
    free cores).
  - If the grep missed another writer, parallel runs would corrupt each other. The acceptance
    test (T10) is there to catch that.
- **CI:** no sweep (one path takes minutes; `ci.yml:57-61` runs one fast build); T1-T9 on fixtures.
- **Offline, the owner's release path:** `sweep --singles --named`, then `rank`, then
  `paths-publish`, then `build --only "Assess fork options"` and `build --only "Publish the path
  ranking"`. The dof gate from `rebuild_all.sh:9` becomes a precondition in `paths-publish`: the
  default run's dof must equal the main build's dof.

## 4. Evaluation

**One record per path:** the index entry, `summary.json` and the ranking row, joined on the path
id.

| Item | Status | Source |
|---|---|---|
| Ladder checks | Exists | `theories/pm/__init__.py:155-171`, `rank.py:93-99` |
| Gates | Exists | `rank.py:93-99` |
| Scoreboard | Exists | `results.py:69` |
| Own-row chi2 and dof | Exists | `ranking.py:38` |
| Missing tiers | Exists | `rank.py:140` |
| `chi2_common` over the same rows | New | See below |
| `n_not_evaluable` | New | See below |
| `for` / `against` | New | See below |
| `no_go` label and reason | New | See below |

- **chi2 over the same row set.** `rank_entries` intersects the predicting row ids over every
  ranked path (the ids come from `PmAnchors.scored_rows`, `theories/pm/__init__.py:113-121`) and
  computes `chi2_common` and `n_common` for each row.
  - The owner set the rule (`rank.py:3-9`), so the smallest change reports `chi2_common` as a
    column and leaves tier 4 alone.
  - Switching tier 4 to `chi2_common` is a ruling for the owner.
  - Until then, a path that scores fewer rows shows `rows_lost` = main's predicting rows minus
    its own, listed under `against`, so dropping rows is never hidden.
- **`n_not_evaluable`.** The count of `status == NOT_EVALUABLE` in the path's
  `canonical_values.json`, plus the main rows the path did not score.
- **`for` / `against`.**
  - `for`: rows whose |sigma| fell compared with main.
  - `against`: rows whose |sigma| rose, failing ladder checks, gates the path fails and main
    passes, `rows_lost`, and the NOT_EVALUABLE ids.
  - `alignment`: the existing `consistent` tier.
  - `evidence`: `run_log` and `build_status` failed steps.
- **No-go label.** A path is no-go when its departure includes a DISABLED option (`model.py:13`).
  - The reason is `kill_condition`, or else `consequence` (`model.py:103,83`), plus `certainty`.
  - For named paths, the reasons of every DISABLED option in the path are listed.
  - A no-go path is still ranked. It keeps its label at every rank and is never adopted
    automatically (`accept` remains an explicit act).
- **Rank change as a finding.** `cmd_rank` reads the previous `--out` file before overwriting it
  and writes `changes: [{path_id, rank_previous, rank, engine_previous}]`.
  - The publisher copies this into `index.findings`, together with a no-go path whose rank or
    `chi2_common` moved, a path that moved between computed and not computed, and retired ids.
  - `paths.html` lists the findings. They are never applied silently.

## 5. Site

- **The switcher stays where it is.** It is the sticky top bar off main (`pm-path-context.js:253-277`)
  and the chip on main (`:279-287`).
  - Smallest addition: a `<select>` in the bar and the chip, filled from `index.paths` and grouped
    as main, considered and no-go. `select()` (`:231`) does the switching. The paths page stays
    the full list.
- **The URL:** `?path=<id>` wins, then sessionStorage, then main (`:85-94`). Internal links keep
  `?path=` (`:313-325`). Unchanged.
- **How pages load the chosen set:** the fetch overlay (`:195-211`) needs no change to any page.
  Three changes make it borrow nothing:
  1. **A file the path did not write.** `path_patch` skips it today (`publish.py:96-97`) and the
     client serves main's file (`pm-path-context.js:201`). Change: publish `{"absent": true}`;
     the client answers with a NOT_EVALUABLE stub,
     `{"status":"NOT_EVALUABLE","note":"not produced on <id>"}`, and lists the file in the bar.
  2. **A sha256 mismatch.** Today the client shows main with a notice (`:207`, `NOTICE` `:16`).
     Change: show the stub, because main's value is not this path's.
  3. **Volatile keys.** `excluded_keys` (`publish.py:255-257`) are left unpatched, so main's noisy
     value shows on the path. Change: publish them as `volatile_ops`, applied but not counted
     in `changed_values`.
- **What a page shows for NOT_EVALUABLE.** One formatter, `PMPath.formatValue(entry)`, is added to
  `window.PMPath` (`:348`). It returns "not evaluable on this path (<note>)" when the status is
  NOT_EVALUABLE or the value is null.
  - The parameter, formula and section renderers call it. L10 picks the call sites and owns
    those files.
  - Assumed, not measured: today a null value renders as a dash or blank.
- **The no-go mark on every page.** The bar is on all 21 pages (measured), so the mark is put in
  the bar.
  - When `entry.no_go` is set, the bar turns red and reads "NO-GO path: <reason> (<certainty>)".
    This replaces the plain status word (`:258-264`).
  - The chip's `<select>` marks no-go options too.
- **The paper per path.** `sections.json` is JSON and is fetched by `pm-section-renderer.js` and
  `pm-paper-renderer.js`, so the HTML paper is overlaid per path already.
  - **PDF:** main only by default, because fast builds leave out "Generate PDF paper"
    (`build.py:442-444`).
  - Named paths may get `paths/<id>/paper.pdf` from a non-fast offline build (about 1 MB each,
    measured from main). Its cost was not measured.
  - Single departures get no PDF. Their HTML paper says to use the main PDF and names the path's
    departures.
