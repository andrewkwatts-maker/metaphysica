# P10 proposal: reader levels, generator-first (2026-11-11)

Angle: start from the engine. A reader page is the output of one build step that reads the
registry artifacts of the path being built, so a number on a level 1 page has the same source,
formatting and status label as the paper. The design goes as far as the engine needs and does not
choose the wording of the prose.

Brief: `docs/plan/programme/P9_P10_DESIGN_BRIEF.md:51-72` (questions), `:74-78` (rules).

## 1. Content map

Generator-first says only how the map is held. It is one data file, `topics.yaml`, and the
renderer refuses a topic that lacks any of these fields:

| field | meaning |
|---|---|
| `slug`, `title` | page `Pages/learn-<slug>.html` |
| `levels: [1, 2, 3]` | all three are required, so the skeleton is the same at every depth |
| `leads_to` | the level 4 page and anchor (for example `sections.html#...`); a test checks that it resolves |
| `quantities`, `claims` | the ids the topic uses; a test checks that the template uses exactly these |

The first map is the primer's sections (`primer_v1.html:162-616`). Each one names its level 4 page
from the existing site set (`website/Pages/`: geometric-framework, sections, parameters,
falsification, paths, formulas):

| primer section | slug | level 4 page |
|---|---|---|
| 1 Dimensions you cannot see | dimensions | geometric-framework.html |
| 2 Why the hidden shape matters | waves | geometry-to-physics.html |
| 3 Counting holes | holes | geometric-framework.html |
| 4 Curvature and the flat torus | curvature | geometric-framework.html |
| 5 The master action | action | sections.html (action section) |
| 6 Two clocks and a term that cancels | two-clocks | sections.html |

The block types in the primer suggest a level split. "Picture it" notes become level 1, "The maths"
notes become levels 2 and 3, and status notes appear at every level. The prose is the content lane's
to write.

## 2. Source format in the engine

A new package, `src/metaphysica/reader_levels/`, holds data and templates only and makes no
physics imports:

```
reader_levels/topics.yaml        # the content map above
reader_levels/quantities.yaml    # qid -> registry binding (the only place a source is named)
reader_levels/claims.yaml        # cid -> its quantities, status source and text per status
reader_levels/templates/<slug>.html   # three level blocks plus shared figures
reader_levels/templates/_notice.html  # "speculative and unvalidated" notice, included by every level
reader_levels/allowed_numerals.yaml   # numerals that are not framework numbers, each with a reason
```

PyYAML is already a dependency (`pyproject.toml:64`). No template engine is added, because the slot
syntax is small enough to parse with one regular expression:

- `{{q:qid}}` is replaced by the value, already formatted by the build.
  `{{q:qid|unc}}` adds the uncertainty and `{{q:qid|unit}}` adds the unit.
- `{{claim:cid}} ... {{/claim}}` wraps a sentence. The renderer adds the status badge and, when the
  status on this path differs from the one the sentence was written for, swaps in that status's text.
- `{{scale:qid|log|1e1..1e10|30..444}}` gives an SVG coordinate computed from a quantity. A diagram
  whose geometry encodes a framework number (the chi-square axis, `primer_v1.html:586-593`) uses
  this slot and never a typed coordinate.
- `{{include:_notice}}`.

A binding sketch (`quantities.yaml`). The ids are real: `kill_switch_rows.py:12` and
`canonical_values.py:331`.

```yaml
tau_p:   {from: "parameters.json#/parameters/proton_decay.tau_p_years", fmt: {sci: 2}, unit: "years"}
w0:      {from: "canonical_values.json#/rulings/w0/value", fmt: {sig: 3}}
b2:      {from: "parameters.json#/parameters/topology.b2/value", fmt: {int: true}}
```

`canonical_values.json` has the top-level keys `note`, `registry_drift`, `rulings` and
`schema_version` (measured). The live `parameters.json` has no `topology.b3` row. b3 is computed at
access (`canonical_values.py:578-584`), so S1 must publish b3 as a row before a template can use it.

Each `from` is a JSON pointer into a file in this build's `AutoGenerated/`. The renderer never
imports `canonical_values` or the variants module. Because it touches no fork, the fork-read
tracking (`build.py:664-697`) records nothing for it, and its dependence on the path comes only
through the artifacts it reads. Formatting happens once, in Python. The page JS only swaps strings
and does no number formatting, so a page and the paper cannot round the same value differently.

Status mapping is one table in `reader_levels/status.py` and reuses
`NON_PREDICTION_STATUSES` (`simulations/PM/validation/observables.py:38-44`):

| registry status | label on the page |
|---|---|
| DERIVED, GEOMETRIC, PREDICTED, COMPUTED, DERIVED_RG | derived |
| FITTED, FITTED_COMPOSITE, RETRODICTED_VARIANT, CALIBRATED | fitted |
| ANSATZ | ansatz |
| ESTABLISHED, MEASURED, ANCHORED, INPUT | input (measured data; it is not a claim) |
| NOT_EVALUABLE (`canonical_values.py:140-150`) | not evaluable on this path |
| any other (VALIDATION, POLICY, NOT_PREDICTED, FOUNDATIONAL, SYSTEM) | build error until the owner maps it |

"Falsified" is never computed by the renderer. It is read from a verdict that already exists: a
kill switch `verdict` in `falsification_report.json` (`detailed_risk_analysis.<switch>.verdict`,
rows named in `kill_switch_rows.py:10-16`), or an identity in `identity_ledger.json`
`broken_on_adopted`. A claim declares which verdict it follows in `claims.yaml`. Note that
canonical_values records falsified candidates only in free text (`canonical_values.py:13`, `:373-376`)
and has no field for them, so those claims stay unbound until such a field exists.

Diagrams are inline SVG in the topic template. Colours come only through `var(--token)` on classes,
with the tokens on `:root` and redefined for dark mode, as in the primer (`:8-28`). The literal check
(section 5) also rejects a hex colour or a `fill="#..."` inside a template SVG. Interactive widgets
(the n-slider, `primer_v1.html:490-494`) keep their formula in a JS file, and their default value and
range come from `{{q:...}}` slots written into data attributes.

## 3. Generation

A build step `("Render reader levels", [python, "-m", "metaphysica.reader_levels.render"], False)`
goes in `STEPS` directly after "Publish the path ranking" (`build.py:466`). By then everything it
reads is written: canonical values `:253`, identity ledger `:276`, falsification oracle `:362`,
statistics refresh `:373` and path ranking `:466`. It must also follow the template copy (`:158`),
because it writes into `Pages/`. Its outputs are:

1. `AutoGenerated/reader_values.json`, which depends on the path. Its schema:

```json
{ "schema": "reader_values/1",
  "selection": {"<fork>": "<option>"},
  "quantities": {"tau_p": {"display": "…", "unc": "…", "unit": "years",
                           "status": "derived", "reason": null, "source": "parameters.json#/…"}},
  "claims": {"<cid>": {"status": "derived|fitted|ansatz|falsified|not_evaluable",
                       "text": {"1": "…", "2": "…", "3": "…"}, "evidence": "falsification_report.json#/…"}} }
```

   `selection` holds the departures from the default and is `{}` on main.
2. `Pages/learn-index.html` and `Pages/learn-<slug>.html`, rendered with this build's values. Every
   page carries a generated marker like `overview.py:45-47` ("edits inside are overwritten"). Pages
   stay flat in `Pages/`, matching the existing relative links.

How it follows the P9 path choice:

- In a sweep, each path build runs the step too. `publish.py` diffs only `AutoGenerated/*.json`
  (`testground/results/publish.py:43-45`), so the HTML pages of a path build are discarded and
  `reader_values.json` enters that path's patch like any other artifact. The paths need no extra HTML.
- On the site, `js/pm-reader-levels.js` fetches `AutoGenerated/reader_values.json`.
  `pm-path-context.js:213-221` overlays that fetch with the chosen path's patch.
- A guard against borrowed values: the loader compares the file's `selection` with the `selection`
  of the chosen path's entry in `paths/index.json`, which every entry carries (measured). When they
  differ, every slot shows "not available on this path" and nothing from main is shown. This closes
  three gaps in which main's file reaches a path page unchanged:
  - a path build that did not write the file is skipped (`publish.py:96-97`);
  - a file that cannot be verified gets no entry (`publish.py:108-109`);
  - when a patch fails, the overlay returns the base file (`pm-path-context.js:200`, `:206`).

  `pm-path-context.js` labels that last case "showing main" (`:16`). That is acceptable for
  other pages but not for reader pages.
- Before the fetch, on any non-main path, the loader blanks every slot. Main's values, which are
  baked into the HTML, are therefore never visible on a path page, not even briefly.
- A quantity that is NOT_EVALUABLE renders as `<span class="pm-q pm-q--ne" title="<reason>">not
  evaluable on this path</span>` and its claim's badge reads "not evaluable". The reason comes from
  the entry's `note` (`canonical_values.py:140-150`). It never falls back to another value.
- A falsified claim renders with the badge "falsified on this path", the evidence pointer and that
  claim's `falsified` text. Every claim in `claims.yaml` must give text for each status it can reach,
  so a success sentence cannot sit next to a falsified badge.
- The path bar from `pm-path-context.js:253-300` already shows no-go labels, and P9 owns that.
  Reader pages include the bar and do not repeat the label.
- No PDF is made for reader pages; this angle has no reason to add one.

  (`:22`), stores it under `pm-reading-level` (`:36`) and validates against `LEVELS` (`:37`).

## 5. Checks (each is a pytest test over the templates or the rendered output)

1. **No literal framework number.** This test scans `templates/*.html` with slots removed. It checks
   text nodes, text inside SVG, and `aria-label`, `title` and `alt`. It ignores SVG geometry
   attributes (`x y cx cy r d points viewBox width height`). Any digit run fails unless
   `allowed_numerals.yaml` lists it with a reason, such as "180 (degrees in a flat triangle)" or a
   heading number.
   - Structural integers such as 26, 13, 4 and b3 are framework numbers and must be slots. b3 changes
     with the path: seed_24 was retired for seed_43_joyce (`canonical_values.py:21-24`).
   - The primer would fail this check today, on the aria-label at `:570` among others.
   - A second test feeds the rendered HTML pages to the prose-drift audit
     (`generate_prose_drift_audit.py:90`), which today reads only `sections.json`.
   - The hardcode audit inspects `.py` files only (`generate_hardcode_audit.py:92`), so it is not
     reused here.
2. **Coordinates encoding numbers.** No test can prove that a typed coordinate encodes a number.
   The rule is therefore structural: a `<figure data-encodes="qid ...">` must contain at least one
   `{{scale:...}}` slot for each qid it names. Review catches a figure that omits the attribute.
   This is a known limit.
3. **Every claim is labelled.** On the rendered output, every `.pm-q` sits inside a `.pm-claim`, and
   every `.pm-claim` has `data-status` in {derived, fitted, ansatz, falsified, not_evaluable}, or it
   holds only `input` values. Every level block opens with `_notice`. The test runs on the main build
   and on a fixture path whose artifacts contain one NOT_EVALUABLE value and one falsified verdict.
4. **No borrowed value.** On the fixture path with a value missing, the rendered value is `null` with
   status not_evaluable, and the main value's string appears nowhere on the page.
   A JS test, beside `tests/js/path_context.test.mjs` (`pm-path-context.js:18`), checks that a
   `selection` mismatch blanks every slot.
5. **An unmapped status fails the build.** If `status.py` meets a status that the table above lacks,
   it raises.
6. **Reading level.** These pure functions over the text of each level block reuse the sentence and
   markup stripping in `generators/prose_lint.py:34-43`. The thresholds are assumed and are to be
   calibrated on `primer_v1.html` in S3:
   - Mean words per sentence: level 1 at most 18, level 2 at most 24, level 3 at most 30. The maximum
     sentence length is `MAX_WORDS` = 40 (`prose_lint.py:24`).
   - Flesch-Kincaid grade, using a syllable heuristic and no new dependency: level 1 at most 10,
     level 2 at most 13.
   - At level 1, a glossary term must be defined in the same block before its first use, and there is
     no maths markup (`class="m"`, `$...$`) outside a "The maths" note.
   - Level 3 must contain at least one maths block for each topic.
7. **The map is consistent.** Every topic has all three levels. Its `quantities` and `claims` equal
   the slots its template uses. `leads_to` names an existing page in `website/Pages/`. No
   `learn-*.html` file exists in `src/metaphysica/website/Pages/`, so no copy is kept by hand.
