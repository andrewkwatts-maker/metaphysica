## 1. Content map

A topic is a list of claims. A claim has one id, the same at every level, and these slots:

| Slot | L1 public | L2 enthusiast | L3 graduate |
|---|---|---|---|
| `hook` (Picture it) | always | one line | optional |
| `claim` | words, slot values | words and named physics | standard terms |
| `maths` | arithmetic only | algebra | the statement with indices |
| `assumption` | one plain sentence | named | named, with its registry key |
| `status` | chip and fixed sentence from data, identical at every level |
| `deeper` | simpler and deeper links to the same claim, and the level 4 link (bold at L3) |

Every claim exists at all three levels. The assumption's wording varies by level. Its key (`assumption="<registry
key or fork id>"`) and the claim's label are the same at every level. Prose never states its own status. The
sentence comes from `phrases.yaml`, so a path that changes a status cannot leave the prose saying the old one.

## 2. Source format in the engine

A package `src/metaphysica/reader_levels/`: `__init__`, `labels`, `values`, `render` and `checks` modules;
`topics.yaml`, `quantities.yaml`, `glossary.yaml`, `phrases.yaml`, `allowed_numerals.yaml`; `topics/<id>.html`, one
file per topic with every claim's three levels side by side (an author who softens level 1 sees the level 3 caveat);
`topics/_strip.html`, `_notice.html`, `_head.html`. Each claim names where its status comes from:

```html
<claim id="holes-families" status-from="fork:n_gen_source" assumption="n_gen_source">
  <l1>…{{q:n_gen|words}}…</l1> <l2>…</l2> <l3>…</l3> <when label="ruled_out"><l1>…</l1> …</when></claim>
```

`status-from` is one of `param:<key>` (the registry status), `ledger:<key>` (the parameter ledger's class),
`fork:<id>` (a chosen option is Ansatz; a DISABLED option is Ruled out), `verdict:<pointer>` (fact 8, or
`narration#/claims/betti/on_reachable_family`), or `standard` (textbook physics, label Measured, allowed only when
the claim binds no framework quantity). No label is typed by an author. A claim with no source fails check 3 and
is listed as a gap for the owner.

Slots (double braces do not collide with CSS or SVG): `{{q:qid}}`, `{{q:qid|unc}}`, `{{q:qid|unit}}`,
`{{q:qid|words}}`; `{{scale:qid|log|lo..hi|x0..x1}}` for an SVG attribute that encodes a number;
`{{include:_strip}}`. An unknown slot raises, as `geometry_narration.render` does (`:575-578`). Each
`allowed_numerals.yaml` entry is `{numeral, topic, context, reason}`, where the reason is `standard`, `analogy` or
`arithmetic`. A construction number is never allowed.

Bindings in `quantities.yaml` are pointers into this build's `AutoGenerated/`, plus `narration#/...` (fact 6):

```yaml
b2:      {from: "narration#/claims/betti/b2", fmt: {int: true}, label_from: "fork:b3_seed"}
n_gen:   {from: "parameters.json:topology.n_gen", fmt: {int: true}}
ranking: {from: "path_ranking.json#/...", global: true}
```

A quantity with no registry status names `label_from`. A `global` quantity comes from an all-path file: it is baked
into the HTML, the same on every path, and never written to the reader JSON (fact 3). R1 confirms each pointer on a
real build. Formatting happens once, in Python. Page JS swaps strings and attribute values and computes nothing.

Reader labels (`labels.py`; fact 12 plus the statuses the engine declares):

| Reader label (L1 words) | Registry statuses | Chip |
|---|---|---|
| Derived ("worked out from the shape") | DERIVED, GEOMETRIC, PREDICTED, PREDICTIONS, COMPUTED, DERIVED_RG | neutral |
| Fitted ("tuned to match a measurement") | FITTED, FITTED_COMPOSITE, CALIBRATED, RETRODICTED_VARIANT; ledger FITTED | amber |
| Ansatz ("assumed, not derived") | ANSATZ, SPECULATIVE, TOPOLOGY_CANDIDATE; ledger ANSATZ; `fork:` | amber |
| Ruled out ("disagrees with measurement") | FALSIFIED, FAILING; a failing `verdict:`; a DISABLED option | red |
| Measured ("known physics, not the model's claim") | MEASURED, ESTABLISHED, ANCHORED, INPUT; `standard` | grey |
| Not evaluable ("this path cannot work it out") | NOT_EVALUABLE | grey, hatched |
| no label | SYSTEM, VALIDATION, FOUNDATIONAL, TERMINAL, TENSION, EXACT, POLICY, NOT_PREDICTED | build fails if bound |

DERIVED_RG, INPUT, FAILING, POLICY, NOT_PREDICTED, NOT_EVALUABLE are not in today's site file; seven mapped statuses
are ambiguous (owner question 2). Level 2 adds the registry word in brackets; level 3 links it to the glossary.

Diagrams are inline SVG in the topic file. They are coloured only by classes whose colours are tokens in
`css/pm-learn.css`: a dark set (the site default) and a light set under `prefers-color-scheme: light`, as the
primer does (`primer_v1.html:8-28`). The header and the P9 bar stay dark bands in both themes, which is accepted.
Each SVG keeps `role="img"` and an `aria-label`. A figure that encodes a value declares `data-encodes="qid ..."`.
Its `{{scale:...}}` attributes are computed in Python into the reader JSON's `figures`, so on a path JS sets that
path's coordinates. A slider (topic 8) steps through a precomputed `series` in the reader JSON and holds no formula.

## 3. Generation

- Step `("Render reader levels", [python, "-m", "metaphysica.reader_levels.render"], False)`, the last row (fact
  1). It reads `parameters.json`, `parameter_ledger.json`, the rigor report, the falsification report, the identity
  ledger, the action ladder, `variants.json`, the path ranking and the option assessment, and it calls `narrate()`.
  The fork-read tracking records the forks it reads, which is correct: the step depends on the path.
- Outputs:
  1. `AutoGenerated/reader_levels.json`: `{"schema": "reader_levels/1", "quantities": {qid: {display, unc, unit,
     label, status, reason, source}}, "claims": {cid: {label, evidence, text: {"1","2","3"}}}, "figures": {fig:
     {"<el>.<attr>": str}}, "series": {sid: [[str, ..]]}, "strip": {verdict_phrase, chi2, rows}}`. It holds no
     selection, stamp or global quantity, so a path whose reader values equal main's adds no op and stays inert.
     Path builds run the step too; `publish.py` keeps only their JSON, so one HTML set serves every path.
  2. `Pages/learn.html` (chooser) and `learn-1.html` to `learn-3.html`, with main's values baked in, readable with
     no JS and in print. Code-made parts (generated marker, build date and commit, level bar) carry `data-pm-chrome`.
- **Before paint.** `_head.html` holds a blocking inline script (ten lines at most) that applies P9's choice rule
  (`?path=`, then sessionStorage `pm.path`) and, for any id but main, sets `html.pm-path-pending`; `pm-learn.css` then
  hides `.pm-q`, claim text and `[data-encodes]` figures, in print too, so main's values never paint under a path.
- **Filling.** `js/pm-learn.js` waits for `pm-path-context.js`. If it settles on main (an unknown id reverts,
  `pm-path-context.js:337-339`), the script clears the class and keeps the baked values. Otherwise it fetches
  `reader_levels.json` through P9's loader. A 424 or withheld answer sets every slot to "Not built for this path",
  and the strip says "Results for this path were not built". A qid, claim or figure missing from the file shows
  "Not built" and is never left at main's value. That covers a key P9 withholds instead of patching.
- **NOT_EVALUABLE.** The slot renders `<span class="pm-q pm-q--ne" title="{note}">` with "this path cannot work this
  out". Level 3 prints the note, and the chip reads "Not evaluable". A figure whose qid is NOT_EVALUABLE is replaced
  by that phrase. If `all_reads_were_live` is false, every narration quantity is NOT_EVALUABLE with that reason.
- **Ruled out on the path.** The claim stays, with the red chip, its evidence and the `when` block for the label
  the path gives. If no block exists for that label, all three levels get the fixed fallback for it from
  `phrases.yaml` ("On this path this claim does not hold: {evidence}"). A success sentence never sits beside a red
  chip. The topic's first line counts its ruled-out claims.
- **No-go path.** Only JS knows the path (fact 9). `pm-learn.js` reads the chosen entry from `PMPath.index()`. When
  `nogo.is` is true, the strip on all four pages adds "This path is rejected (no-go): {reasons[0]} ({certainty}). It
  is still run and scored." The P9 bar shows its own label as well.
- **With no JS** (and for crawlers) a `?path=` URL shows main's page, its strip saying "Values for the main path",
  a `<noscript>` line saying other paths need JavaScript; the canonical link is the bare file.

## 4. Navigation

`Pages/learn.html` is the chooser (strip, three cards, topic list, "continue"); `Pages/learn-{1,2,3}.html` are the
levels, anchored by topic and claim ids. The level is in the file name, so a shared link opens the level it names;
there is no `?level=`. The link keeper (`pm-path-context.js:313-325`) keeps `?path=` but skips `#`-only hrefs
(`:318`), so level links are always `learn-N.html#id`. `Pages/beginners-guide.html` becomes a hand-written stub in
`website/Pages`, copied by the build: a link and a meta refresh.

- **Picking a level.** Three cards: "New to physics, or did it at school", "I studied some physics at university"
  and "I have a physics degree". Each quotes claim `holes-betti` at that level. Under them: "Not sure? Start at
  level 1; every section has a harder link." No quiz.
- **Changing level.** A sticky bar under the path bar reads "Level: School · Undergraduate · Graduate · Research",
  with plain links and `aria-current="page"`. A short script points them at the claim in view. "Research" goes to
  the current topic's first `leads_to`, its primary page. Every topic ends with "This topic at level 1 · 2 · 3 ·
  the research page".
- **Keeping the level.** The URL is the state. localStorage `pm.level` (try/catch, never a redirect) only feeds
  "Continue at level 2, Counting holes" on the home card and the chooser. The toggle's `pm-reading-level` is not shared.
- **From the home page.** A "Start here" card follows the research notice (`index.html:553-566`, which stays first)
  and replaces the pill at `index.html:977`. The header link `pm-header.js:36` becomes "Learn" -> `learn.html`; P9's
  W4 makes that edit (section 6). Other inbound links reach the stub.
- **Up and down.** Up: each topic's `leads_to` (L1 and L2 add "the glossary maps the research pages' status words").
  Down: each mapped level 4 page gets "New to this? Read it at level 1 · 2 · 3" from the map, by its template (R8).
- **Status strip** on every learn page, before the first heading, never in `<details>`, and printed: "Speculative
  and unvalidated. Not peer reviewed. Fit to measurements: {verdict phrase}. Path: {label}." Levels 2 and 3 add
  "chi2 {chi2} over {rows} rows". The verdict comes from `summary/status` (fact 7), never from `statistics.json`'s
  "MAJORITY_VERIFIED" (`:37`).

## 5. Checks (pytest unless marked JS)

1. **No literal framework number.** Scope: `topics/*.html`, the `topics.yaml` titles, `glossary.yaml` and
   `phrases.yaml`, with slots removed: text nodes, SVG `<text>`, `aria-label`, `title` and `alt`, but not SVG
   geometry. A digit run, or a number word from "three" up, passes only if an `allowed_numerals.yaml` entry names
   its numeral and topic and its `context` string is in the same text node. A second pass on the rendered pages
   checks digits outside `.pm-q` and `[data-pm-chrome]` the same way. `js/pm-learn.js` may hold no numeric literal
   other than 0, 1 and -1, so no formula can live there. The primer fails this today (e.g. `:570`).
2. **Encoded coordinates.** Each `data-encodes` qid has a `{{scale:...}}` slot in its figure, and each slot has
   a qid. A figure that binds a qid in text declares `data-encodes`, or `data-encodes="none"` with a `data-reason`.
   Limit: a hand-typed coordinate in a figure that binds nothing goes undetected.
3. **Every claim labelled.** Over claims, not slots: each has a resolvable `status-from`, a `data-label` that is
   one of the six labels, and a chip and sentence that agree with the built path. A quantity with no registry
   status names `label_from`.
4. **Caveat parity.** Each claim id exists at levels 1, 2 and 3 with the same label and `assumption` key.
5. **Labels cover the registry.** A bound unmapped status raises; a test lists built statuses with no label.
6. **No borrowed value.** Python: a fixture with one NOT_EVALUABLE quantity renders the phrase, not main's string.
   JS, beside `tests/js/path_context.test.mjs`: a 424 answer gives "Not built" in every slot and figure; a qid
   missing from the file gives "Not built"; on a non-main path the pending class is set before `pm-learn.js` runs.
7. **Strip.** Python: on all four pages it precedes the first `<h2>`, outside `<details>`, verdict filled. JS: a
   fixture entry with `nogo.is` gets the rejection line on all four pages; one without it does not.
8. **Reading level**, with no new dependency: mean words per sentence L1 ≤ 16, L2 ≤ 22, L3 ≤ 30; no sentence over
   40; Flesch-Kincaid by syllable heuristic L1 ≤ 9, L2 ≤ 13, rising L1 < L2 < L3 in every topic; no TeX at L1;
   glossary terms linked on first use at L1; a maths note in every L3 topic. R3 calibrates the thresholds.
9. **Banned strings** on learn pages: "verified", "proven", "confirmed", "✓", "MAJORITY_VERIFIED",
   "27-dimensional", "27D", "25D". `forbidden_phrases()` (`geometry_narration.py:581`) finds nothing.
10. **Links and map.** Every `leads_to` exists in `website/Pages/` or `foundations/`; every `sections.html#id` is
    in the build's `sections.json`; after R8, mapped pages link back. Each topic's `quantities` and `claims` equal
    the slots its file uses. No `learn*.html` exists in `src/metaphysica/website/Pages/`.
11. **Themes.** No topic file has a literal `fill`, `stroke` or `style` colour (only classes, `none` and
    `currentColor`). Every token used in `pm-learn.css` is defined in both the dark and the light set.
12. **Every label has text.** For each claim, every label its `status-from` can produce has a `when` block or the
    phrase fallback. A fixture that forces an unwritten label renders the fallback at all three levels. R9 runs
    this over every published path's `reader_levels.json` and lists the claims that used the fallback.
