# P9 design: a build per path, a site that switches paths (2026-11-11, revised)

Merged from `P9_proposal_smallest-change.md` (SC), `P9_proposal_incremental.md` (IN) and `P9_proposal_site-first.md` (SF), then revised for the review of 2026-11-11. Read-only survey on branch `site-review`. Paths are relative to `src/metaphysica/` unless they start with `docs/`, `tests/`, `.github/` or `PrincipiaMetaphysica/`. This is a design; it asks for no code.

**The model is speculative and unvalidated.** No path, rank or score is a prediction or a validation. Section 5 prints that statement on every path page, and T5 checks that it is there.

Taken from: SF's id kinds, `path_patch/2` and the withholding loader; SC's adapter, no-go rule, `rows_lost` and lane split; IN's per-step reads and measured step times. Rejected: IN's `+` combination id (it fails `ID_RE` and decodes to a space in a query string); IN's step-trace cache as the default (kept as W11, deferred); SC's stub JSON body in place of a whole file (it breaks loaders); SC's helper name `formatValue`, which is taken (`website/js/pm-constants-loader.js:1064`).

## 1. Path identity

| Kind | id | Example |
|---|---|---|
| default | `main` (`selection_id` returns `active`, `variants/selection.py:125-131`) | `main` |
| single | `<fork>--<option>` (today's form) | `chi_eff_route--seed_dependent` |
| repaired single | the requested single's id; `departures` lists both forks, `repair` names the second | `b3_seed--seed_7_joyce` (runs with `n_gen_source=chi_eff_over_48`) |
| owner-named | `c_<slug>` | `c_seed24_thawing` |
| unnamed combination | `x_<selection_id>` (12 hex) | `x_9d35e2f8fbd9` |

- Every id matches the existing `ID_RE`. `enumerate_runs` drops its `--` requirement and checks the kind prefix instead.
- Ids come from the departures after `canonical_departures` (`variants/selection.py:120-122`). A new fork whose default is its legacy option changes no id (T9).
- One function, `path_id(selection, named, requested=None)`, in a new `testground/results/path_ids.py`, is the only place ids are made. The publisher and `rank.load_entries` (`testground/rank.py:196`, which uses `root.name` today) both call it. The 16-hex digest (`testground/configurations/model.py:47-54`) stays internal.
- Every index entry stores `selection_id`, `departures` and `selection`. The publisher refuses a `c_` name whose `selection_id` differs from the previous index. It lists under `retired` a single whose option became the default, and writes a `changes` row when a repair changes.
- **Which paths are built: every one of the 69 options, and none is skipped.** 63 run as plain singles. 4 run as their unique repair, labelled with the requested single. The 2 refused singles run plain under a new `sweep --include-refused`, as the October driver ran `b3_seed=seed_24`. Any selection that violates a constraint, refused single or named path, is still run. It is labelled no-go with the violation as its reason (section 4). `not_computed` means only that a run failed, and it carries that run's reason. T18 checks that all 69 options are covered.
- **Named paths:** `theories/pm/named_paths.json`, `{slug: {fork: option}}`, created empty. `load_named` checks each entry through `check_selection(data, where)`, the body of `load_selection`, which W1 splits out (`selection.py:132-147`).
- **Who decides:** the owner edits `named_paths.json`; an agent may propose a name in a commit that records it in DECISION_LOG. The assessment's `candidates` (configuration digests, `testground/assessment/recommend.py:72`) are not built on their own. A candidate that is already a published path is flagged `candidate` in its index entry. Any other candidate is built only once the owner names it. `x_` paths from `--joint` and `--sample` are ranked as audit evidence; whether any are published is open question 2.

## 2. Layout

The default path stays in `AutoGenerated/`. Patches stay, because full copies would be about 4.3 GB for 100 paths.

```
AutoGenerated/paths/index.json         metaphysica.paths/2: what the switcher needs
AutoGenerated/paths/changes.json       findings from the last re-run (section 4)
AutoGenerated/paths/<id>/patch.json    metaphysica.path_patch/2
AutoGenerated/paths/<id>/summary.json  the evaluation record (section 4)
AutoGenerated/paths/<id>/files/...     the path's own files: build_status.json, fork_reads.json; plots and paper.pdf (c_ only)
```

`path_patch/2` changes the default from "not in the patch means main" to "not listed means withheld":

```
{"schema":"metaphysica.path_patch/2","path":"<id>","main_build":"<sha256 of main parameters.json>",
 "files":   {"<name>": {"base_sha256": "..", "ops": [..], "volatile_ops": [..]}},
 "same":    {"<name>": "<base_sha256>"},
 "own":     {"build_status.json": "paths/<id>/files/build_status.json", ..},
 "withheld":{"<name>": "missing on path | unverified | failed step <id>"},
 "assets":  {"plots/x.png": "paths/<id>/files/plots/x.png" | null}}
```

- **Global files.** `index.json` lists `global`: `path_graph.json`, `option_assessment.json` and `path_ranking.json`, which are built from all paths, plus everything under `paths/`. On every path the loader serves these unchanged. They are never patched or withheld.
- **`same` is verified.** A name goes under `same` only when the published file's sha equals the fast main run's sha, or `published_ok(published, raw, [], pats)` holds. Otherwise it is `withheld: unverified`. This closes the borrowing route where a full-build file differs from the fast run.
- **`own`.** `build_status.json` and `fork_reads.json` are copied whole from the path's run. They no longer depend on main's sha, so a later `--only` build cannot void them.
- `volatile_ops` carry the path's own values for keys the twin build marks volatile (`publish.py:255-257` leaves them unpatched today, so main's noisy value shows). They are not counted in `changed_values`. W2 measures their size on the October `b3_seed--seed_24` patch; if they more than double it, those keys are withheld instead.
- `index.json` (`metaphysica.paths/2`):

```
{"schema":"metaphysica.paths/2","main_build":"<sha>","engine":{"version","commit","fingerprint"},
 "generated":"..","stale":false,"previous":{"generated","commit"},"global":[".."],
 "paths":[{"id","kind":"main|single|repair|named|combo","label","departures","selection",
   "selection_id","repair","candidate","status":"active|considered|disabled",
   "nogo":{"is":bool,"kind":"disabled|constraint","reasons":[".."],"certainty":".."},
   "rank","rank_prev","rows_scored","rows_total","not_evaluable","inert","failed_steps",
   "built_commit","has_pdf"}],
 "not_computed":[{"id","departures","reason"}],"retired":["<id>"]}
```

- The schema moves to `/2`, not to extra keys under `/1`, because the patch semantics change. The contract moves into the engine repo (`docs/plan/paths/contracts.md`, W2); W10's site commit deletes the site copy.
- **Main's sha and publishing.** Main's per-entry timestamps change every main sha on every build, so a main rebuild withholds every path until the next publish. Main and paths are therefore published in one site commit (open question 4).
- **Size budget** (0.23 MB per path, assumed linear): 69 singles about 16 MB; 100 paths about 23 MB; each named path with its own plots and PDF adds about 4.1 MB (3.2 + 0.94, measured on main). Named paths start at 0. A publish can add that much to the site's git history (deltas not measured).

## 3. Build

- **Question 3 is answered "no reuse".** No step is skipped on a path, because steps read each other's `AutoGenerated` outputs and that data flow is not tracked. This also honours the owner's rule that every path is run and validated. Provisional per-process evidence: 19 of 26 forks are read, `b3_seed` and `chi_eff_route` by all 48 processes, and a departure of an unread fork was inert 12 times out of 12. W7 makes this per step: `METAPHYSICA_FORK_READS_DIR` becomes `fork_reads/<_step_id>/` in `_execute` (`build.py:699`, `_step_id` at `:504`), in-process reads are flushed before the merge, and `fork_reads.json` gains `by_step`. Under `--only`, `_execute` merges into the existing `fork_reads.json` and `build_status.json` instead of replacing them. The map is evidence, not a skip rule.
- **Read audit.** After a sweep, a path whose departed forks no step read must be inert. A break of this goes into `changes.json`.
- **Adapter (SC's G1).** `enumerate_runs` (`publish.py:148`) reads a sweep fingerprint directory, reusing `rank.py:183-193`: the selection from `configuration.json`, `exit` = the first non-zero `stages[].exit` (else 0), `secs` = `wall_s`, `reason` = `reason`, and the id from `path_id`. The scratch driver `rebuild_all.sh` retires (W10's site commit deletes it). Its dof gate (`:9`) becomes a `paths-publish` precondition.
- **Re-runs after a fix.** W9 widens the fingerprint to `*.py`, `*.json`, `*.yaml` and `*.csv` under the package, so a fix to `data/constants/*.json` or a certificate changes it. The main build writes that fingerprint into `build_status.json`, which gives T4 something to compare. A new fingerprint reruns every path, as intended. The run cache only resumes an interrupted sweep (`testground/sweep/execute.py:3-5`). The twin build uses a second `--runs-dir`.
- **Per-path checks.** A fast build runs the validators, ladder and gates. W12 adds a second pipeline stage that runs the artifact tests CI builds for (`ci.yml:44-56`: freshness, phantom-path audit, status whitelist, pass-throughs) against the run root. Its exit goes into `stages[]` and `evidence`. Cost not measured; W12 measures it first.
- **One path's failure** is recorded at three levels and the sweep moves on (`commands.py:124-133`): the step in `build_status.json` (`build.py:527-535`), the run in `run_log.json` (`testground/runner/worker.py:11-15`), and the publish under `not_computed` (whole path) or `withheld: failed step <id>` (per file).
- **c_ paths are full builds.** W6 makes the PM pipeline drop `--fast` for a named configuration (`theories/pm/__init__.py:93-95`), so it draws plots and the PDF. Singles stay fast.
- **Parallel runs (W8)** cover 49 files, not 6. W8a adds T19: no module under `simulations/` derives an `AutoGenerated` path from `__file__`. The 49 current offenders are listed in the test as known failures and must reach 0. W8b moves them onto `METAPHYSICA_OUT` in batches of about ten, rerunning T10 after each batch. W8c removes the junction (`simulations/__init__.py:119-136`) and sets `shared_state=False`. W8a measures one cheaper route first: a private copy of the package per worker, which gives each worker its own junction.
- **Wall clock** (runs = paths + default + twin; serial, `--jobs 1` until W8):

| Paths | at 181 s (October local median) | at 400 s (brief; CI 354 to 416 s) |
|---|---|---|
| 30 | 1.6 h | 3.6 h |
| 69 singles (71 runs) | 3.6 h | 7.9 h |
| 100 | 5.1 h | 11.3 h |

  Each `c_` path adds a full build (at least 579 s, plus the PDF, not measured). The main full build comes on top. After W8, four workers are assumed to divide these figures by four.
- **CI** runs no sweep: one fast build and pytest (`ci.yml:58,61`), plus section 6's tests on fixtures (not T10 and T16, which are slow and run offline). W9 adds one CI job: it checks out `PrincipiaMetaphysica` and runs T4 (site half) and T18 on its `AutoGenerated/paths`. A borrowed or unverified file fails the job on every push. A stale fingerprint is a warning on a push and a failure on a release tag. That makes the PyPI release the Action that stops a stale publish, and the warning is the cue for the offline sweep after a fix wave.
- **Offline release path:** full main build; `testground sweep --singles --include-refused
  --named --jobs 1` (`--jobs 4` after W8); the twin; `testground rank`; `testground paths-publish`; `build --only "Assess fork options" "Publish the path ranking"` (`build.py:459,466`; these files are global, and the `own` files are untouched); the freshness check (W9); one site commit of main and paths together.

## 4. Evaluation

One record per path: the index entry (the switcher's summary) and `summary.json` (the full record), joined on the id. Existing keys: `scoreboard`, `chi2`, `gates`, `certificate`, `n_gen`, `key_values`, `changed`, `inert`, `failed_steps` (`theories/pm/results.py:168-181`). Added:

```
{"for":[..], "against":[..],
 "alignment":{"chi2_own","dof_own","chi2_common","n_common","rows_scored","rows_total","rows_lost","rows_unkeyed"},
 "ladder":{"failed","total"}, "not_evaluable":[{"id","note"}],
 "evidence":{"run_log":"..","build_status":"..","stages":[{"id","exit"}],"failed_steps":[..]},
 "nogo":{"is","kind","reasons","certainty"}, "rank","rank_prev","commit_prev"}
```

- **Ladder checks and gates** already exist (`theories/pm/__init__.py:155-171`, `rank.py:93-99`).
- **chi2 over the same rows.** `load_entries` (W1) carries each run's scored row ids. `rank_entries` (`rank.py:112`) intersects them over every computed path and writes `chi2_common` and `n_common`. A row whose id fell back to its index (`theories/pm/__init__.py:118`) is never matched; it is counted in `rows_unkeyed`. Tier 4 stays each path's own-row chi2 (`rank.py:3-9`, `theories/pm/ranking.py:38`) until the owner rules (open question 1).
- **Fewer rows:** `rows_lost` is main's predicting rows minus the path's. It is listed under `against`, and "scored on n of N" appears beside every rank. Missing tiers are never filled in (`rank.py:140`).
- **NOT_EVALUABLE:** the path's rows with that status in `canonical_values.json` (`simulations/core/canonical_values.py:141-144`), plus main's rows the path did not score, each with its note. Never a value from main. The engine half is W12's (section 7).
- **for / against:** `for` = rows whose |sigma| fell against main; `against` = rows whose |sigma| rose, failed ladder checks, gates the path fails and main passes, `rows_lost`, NOT_EVALUABLE ids.
- **No-go label**, computed at publish and never in JS. A path is no-go when any departure is a DISABLED option (`testground/switches/model.py:13`; `kind: disabled`; reasons from `kill_condition`, else `consequence`, with `certainty` and `decision_refs`, `model.py:83,93,100-105`), or when its selection violates a constraint (`kind: constraint`; the violation text). A no-go path is built, scored and ranked. It keeps its label at any rank and is never adopted automatically.
- **Re-run after a fix wave.** `cmd_rank` (`rank.py:247`) reads the previous ranking before overwriting it and writes `changes`. The publisher writes `paths/changes.json` rows of the form `{id, kind, before, after, commit_prev, commit, why}` for: a path whose rank moved; a no-go path whose `chi2_common`, ladder, gates or rows moved, at any rank (the owner's rule); a move between computed and not computed; a changed repair; a retired id; a read-audit miss. The paths page lists these rows at the top, and none is applied silently.

## 5. Site

- **What the site can show.** The site is static, so a reader can only view combinations that were built: main, the 69 singles, and the named paths. This limit is stated on the paths page and in the switcher.
- **The switcher.** `pm-path-context.js` builds one native `<select>` with optgroups from `PMPath.index()` (`:353`), calling `PMPath.select` (`:231-235`). The groups are Main, Named paths, Single changes (grouped by fork), No-go (still run, collapsed) and Not computed (disabled entries, with the run's reason as the title). Each option shows its rank, "n of N rows" and a no-go badge. A second control, "change one fork", takes the current selection with one fork changed. It goes to the path whose `selection_id` matches, and otherwise reads "This combination is not built; the owner can name it in named_paths.json". It mounts in a slot that `createHeaderHTML` (`website/js/pm-header.js:117`) adds; on the two pages without the header it mounts in the path bar (`pm-path-context.js:253-303`). `Pages/paths.html` stays the full list.
- **The URL.** `?path=` wins, then sessionStorage `pm.path`, then main (`:85-94`). Internal links keep `?path=` (`:313-325`). An unknown or retired id shows "Path <id> is not in this build; showing main" in place of the silent fallback (`:337-339`).
- **How pages load the chosen set.** The fetch overlay stays (`:195-220`), and no page changes.

  | The file is | The loader |
  |---|---|
  | in `global`, or under `paths/` | serves it unchanged |
  | under `files` | checks the sha and applies `ops` and `volatile_ops` |
  | under `same` | checks the sha and serves main's file (verified at publish, section 2) |
  | under `own` | serves the path's copy |
  | anything else, a sha mismatch, a `/1` patch, or `index.stale` | withholds it |

  A withheld file is answered with status 424 and `{"status":"NOT_EVALUABLE","withheld":"<reason>"}`. Each loader takes its error state (`website/js/pm-loading-states.js`); W5 checks each one. The bar lists withheld files as "not built for this path".
- **The other two routes.** The component cache key becomes `pm_<path>_<component>`, so a load on main never serves a path and a load on a path never serves main. `_defaultNamedConstants` is used on main only. On a path, a failed `named_constants.json` gives null, which displays as not evaluable (W0, `pm-constants-loader.js:789-800,456-468`).
- **NOT_EVALUABLE in a page.** `PMPath.display(value, record)` returns "not evaluable on this path", with the record's `note` as its title, when the status is NOT_EVALUABLE or the value is null on a non-main path. Six formatters delegate to it: `pm-constants-loader.js:1064`, `pm-paper-renderer.js:2077`, `pm-tooltip-system.js:105`, `pm-paper-tooltips.js:780`, `pm-certificates.js:202` and `pm-geometry-to-physics.js:18`, and so does `{{param:key}}` (`pm-paper-param-processor.js:10`). Each file exports its formatter for node behind a `typeof module` guard. No page prints `?`, `NaN` or `null`.
- **Speculative status and no-go on every page.** On every non-main path, the bar (built by `mountUi`, `:296-303`) begins "Speculative, unvalidated model; a rank compares paths and validates none." When `nogo.is`, the bar turns red, carries `data-nogo`, and reads "No-go path: <first reason> (<certainty>). It is still run and checked. Nothing here is a prediction." It links to `paths.html#<id>` and is shown in print (`@media print`).
- **Plots.** Images bypass `fetch`. On a non-main path, W0 replaces every `<img>` whose source is under `AutoGenerated/` with "plot not drawn for this path". W6 patches `plots-manifest.json` so each entry points at `paths/<id>/files/...` or carries `not_built_on_path`.
- **The paper per path.** Every path gets its HTML paper from the patched `sections.json`, `core_paper.json` and `{{param:key}}`. PDFs are built only for main and `c_` paths, by their full builds, into `paths/<id>/files/` (`has_pdf`). For a no-go path, "Generate PDF paper" prints the no-go statement and the speculative statement on page 1. The paper page links the PDF when `has_pdf` is set; otherwise it reads "No PDF for this path; print this page".

## Open questions for the owner

1. **Rank rule.** Tier 4 sorts by each path's own-row chi2 (`rank.py:3-9`). Switch it to `chi2_common`, or keep it and show `chi2_common` and `rows_lost` beside it?
2. **Unnamed combinations.** Publish the top-k `x_` paths from a joint or sampled sweep, and how many, or keep them as audit evidence until you name them?
3. **"Still run".** This design reuses nothing. If W11 were adopted, unchanged steps would be reused after a fix. Would that still count as running a no-go path?
4. **Publish cadence.** Main and paths are published together (section 2), and each publish adds up to about 23 MB of patches to 90 MB of history. Publish at every verified checkpoint, or only with a PyPI release? Dropping the per-entry timestamps from `parameters.json` would stop every main rebuild from withholding all paths. Should that be a lane?
5. **Refused singles.** They run plain and are labelled no-go (constraint). Should the 4 repaired singles also run plain, as well as in their repair?
