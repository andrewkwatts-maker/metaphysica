## Method for a history lane (read narrowly)

1. Subjects first: `git log --reverse --format='%h %ad %s' --date=short <range>` to a scratch
   file; read it once.
2. Open only commits whose subject names a model, a claim, a version step, a removal, a
   retraction, a refutation or a ruling: `git show --stat <c>`, then
   `git show <c> -- <one path>` for the paper, config or docs hunk that states the change.
   Never page a whole commit, never open generated output (`AutoGenerated/`, built html).
3. Model state at milestones (first and last commit of the range, and each version step):
   `git grep -n -i -E "signature|shadow|two.time|2[5-7]D|1[0-4]D|b_?3|chi_eff|n_gen|generations" <c> -- <config and paper source paths>`
   limited with `| head -40`. In the old site tree the single source of truth is `config.py`
   (from v12.8); earlier, the paper html and `foundations/`.
4. Stop when every subject that matched step 2 is covered. Say in the file what was not opened.

A docs lane reads its files in full, in parts. The code lane runs the fork report
(`METAPHYSICA_OUT` pointing at a temp directory if a command needs an output directory) and
reads the option records, not the simulations behind them.

## What a lane file holds (250 lines at most)

1. **Era summary**, five lines: the model at the start and at the end of the range (bulk
   dimension and signature, number and dimension of shadows, number of times and where they
   sit, internal space and its construction, b2, b3, chi, the generation formula).
2. **Model timeline**: `| date | commit or file:line | old -> new | reason as recorded |`.
3. **Ideas**, one row each:
   `| id | idea | kind | first seen | last seen | fate | reason recorded | reason type | today |`
   - `kind`: bulk, shadows, time, internal, lattice, topology-number, generations, action,
     gauge, particle, cosmology, identity, other.
   - `fate`: in-force, superseded, retired, withdrawn, falsified, refuted-by-argument,
     never-implemented, unknown.
   - `reason recorded`: a quote of 20 words or fewer with its commit or file:line; `none` if
     the history gives no reason.
   - `reason type`: computed-number (name the code that produced it), data (name the
     dataset), argument, ruling, none.
   - `today`: `fork:option` if `variants` has it, else `no option`, else `prose only`.
4. **Owner's candidates** (below): for each, `seen` with a reference, or `not seen`.
5. **Gaps**: what was skipped and why.

Pipeline, rendering, site-styling and tooling changes are not ideas: one summary line, no rows.
