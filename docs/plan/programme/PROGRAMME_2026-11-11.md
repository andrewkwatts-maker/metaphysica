## Generic checks, sweep speed and the model search (owner, 2026-11-11)
Owner: every switch and path is covered by generic concept and validation code that can be
configured (dimension up or down, application), so one set of scripts tests every path; add
threading when a sweep or a simulation gets slow (a half-hour simulation is the example); keep
adding options and A/B testing paths until a new master action has gravity and the forces built
from the geometry, is falsifiable and agrees with experiment within reasonable tolerances; if
nothing fits, do not force it: reflect on what that means.

- Model spec (P3, P8). A model is data: bulk dimension and signature, how it splits (shadows,
  times, internal space), the class of the internal space with its topological numbers, the
  fields and the terms of the action (`actions.model.Action` already takes `dim`, `signature`,
  fields and terms). Concept and validation code read the spec of the path in force; none types
  26, (24,2), 13, 7 or a Betti number. A check that makes sense on one path only says so and
  returns NOT_EVALUABLE elsewhere.
- One script, every path. Each check runs unchanged on every path of the sweep and on the toy
  theory; a test runs each generic check on at least two specs of different dimension.
- Speed (P9). Measure first: every build writes wall time per step and per path. Budgets: a sweep
  round over 30 minutes, or one simulation over 5 minutes, is a finding and gets work, in this
  order: a cheap screen before any full build, the run cache, paths in parallel processes (24
  cores; `design/P9_PATH_BUILDS.md` W8 removes the shared state that refuses it today), then the
  slow simulation itself. Threads only where the work releases the GIL (numpy, the Rust core);
  otherwise processes. A parallel result equals the serial one (test).
- Search loop (P8), in rounds: (1) candidates from the ideas ledger, from the catalogue of known
  mechanisms by which a geometric action yields gauge fields and chiral matter, and from
  combinations not yet tried; (2) each becomes a disabled option or a new fork on the generic
  code; (3) gates and tolerances are written down before a candidate is scored; (4) screen, then
  a full build for the survivors; (5) a for-and-against record per candidate; (6) the ranking and
  what moved is a finding.
- Gates, in order. G1 the action is written out and its field equations hold on the vacuum. G2
  4D gravity comes out (massless graviton, Newton's constant from the volume). G3 the forces come
  out of the geometry: a non-abelian gauge sector containing SU(3) x SU(2) x U(1), sourced by the
  action, not typed in. G4 chiral fermions in three generations, anomaly-free. G5 at least one
  prediction an experiment can rule out, named with the experiment. G6 agreement with data within
  the tolerance below. Today the path in force stops at G3 (`nonabelian_gauge_source` fails).
- Tolerance (planner default; the owner may change it): a row agrees when the prediction is
  within 2 sigma, sigma being the experimental error and the theory error declared before
  scoring, combined; a path agrees when no predicted row is beyond 3 sigma and the chi2 over the
  predicted rows has p >= 0.01. Calibrated, fitted and ansatz rows count as inputs, never as
  agreement. Many paths are tried, so every claim carries the number of paths tried and a p-value
  corrected for it.
- Stop. Success: a path passes G1 to G6; it is put to the owner as a candidate for the path in
  force. No fit: two rounds in a row add no new family of mechanism and no path gets further up
  the gates. Then that is the result, and P11 carries it: which gate stops every family, which
  no-go theorem binds, and what would have to be added that is not geometry. Nothing is tuned to
  pass, and a no-go stays a no-go.
- Design: `design/P8_MODEL_SEARCH.md`, from `workflows/p8_model_search_design.js`.

## P4 design note (planner)
"Solve" means, for S_26 = Int sqrt|G| [(M_*^24/2) R + Psi-bar i Gamma D Psi]: field equations,
a vacuum that satisfies them, the linearised spectrum on that vacuum, and the 4D effective
action, each as a ladder check that can fail. Expected honest outcome, to be confirmed by code:
vacuum = Ricci-flat product with the holonomy-G2 Y_7 (Psi = 0); massless 4D content = graviton,
b3 moduli scalars with no potential, no non-abelian gauge fields (a compact holonomy-G2
manifold has no continuous isometries, and the action has no form field), non-chiral fermions.
Where the solution does not reach a tabulated Standard Model number, the paper says so and the
number is labelled an ansatz over the topology, not a consequence of the action.
