The adopted path is `b3_seed = seed_43_joyce`: `(b_2, b_3) = (12, 43)`, DERIVED,
ruled 2026-09-22. `src/metaphysica/simulations/PM/geometry/b3_path.py` is the

## 2. The experiment

Two full exports into scratch directories, one per seed, everything else
identical:

```
METAPHYSICA_OUT=<scratch>/default              python -m metaphysica.simulations.run_all_simulations   # exit 72
METAPHYSICA_OUT=<scratch>/seed24 \
METAPHYSICA_VARIANT_B3_SEED=seed_24            python -m metaphysica.simulations.run_all_simulations   # exit 72
```

then the downstream generators in both trees. Both exits were 72
(non-sterile = expected); no other non-zero exit occurred except the two noted
in §5.

**`parameters.json`: 798 rows each, same key set, 183 rows differ.** The seed
propagates properly through most of the tree — `cosmology.b3` 43 → 24,
`particle.b3` 43 → 24, `topology.b2` 12 → 4, `topology.elder_kads` 43 → 24,
`cosmology.w0_thawing` −0.976744 → −0.958333, `topology.k_gimel` 21.818 → 12.318,
`thermal.alpha_T_base` 0.146121 → 0.261799 — and the identifications that break
on the adopted seed say so in their own value field
(`topology.b3_leech_identification` = `BROKEN_ON_ADOPTED_SEED(b3=43,
leech_dim=24)` → `HOLDS(coincidence of seed_24)`). **That is what makes the rest
a defect rather than a design.**

A field that is IDENTICAL under both seeds while its own metadata declares a
`b_3`/`elder_kads` derivation is **SEED-BLIND**, and the diff is the proof.
134 rows are in that class; the whole `geometry.*` block from
`geometric_anchors` (≈115 rows) is in it, and most of those rows are
experimental anchors where being seed-blind is correct (`geometry.theta_13` =
8.54 is the NuFIT value restated, `geometry.w0_observed_DESI` = −0.958 is the
DESI anchor). The rows below are the ones where seed-blindness publishes an
abandoned seed's answer as a result.

### Why the leak is invisible to the framework's own manifest

`variants.py::_dark_energy_betti_adopted()` does not declare which integer sets
`w_0` — it **measures** it, as `n = round(1/(1 + w0))` read from
`cosmology.w0_derived`. Because that row is frozen at −23/24, the fork reports
`selected=b3_24` and the manifest is internally consistent with the abandoned
seed. The leak therefore *authenticates itself*: `variants.json` cannot be used
to detect it, which is why the gate compares against `b3_path` instead.

This also leaves a real question for the author, **not answered here**: the
`dark_energy_betti` option adopted is worded `b3_24: n = b3 = 24, w0 = -23/24`.
After the 2026-09-22 ruling `n = b_3` and `n = 24` are different claims, and the
export currently publishes both (`cosmology.w0_derived` = −23/24 and
`cosmology.w0_thawing` = −42/43, in the same file). Which one the fork means is
an OPEN item; the gate pins the present state either way.

## 4. How the stale bundled snapshot survives its own refresh

`python -m metaphysica.generators.generate_datasheets` is the documented refresh
for `Get()`. It rebuilds `data/constants/*.json` — and reproduces 24 exactly,
under BOTH seeds. The cause is a precedence order:

```
datasheets/constant.py::_load_parameters_json()
    1. metaphysica/data/parameters.json        <-- the STALE snapshot, tried FIRST
    2. $METAPHYSICA_OUT/AutoGenerated/parameters.json   <-- the fresh build
```

So the snapshot reseeds the artifacts that are supposed to replace it. That is
why **A2** is classified as a stale snapshot that a rebuild does *not* fix, and
why `parameter_artifact.py`'s own warning — "the bundled wheel snapshot is
deliberately NOT a fallback … 111 shared rows hold DIFFERENT values" — applies
to `constant.py` as well, which does not honour it.

## 5. What the two runs also turned up

* **`metaphysica.build` halts under the off-path override.** With
  `METAPHYSICA_VARIANT_B3_SEED=seed_24`, `Report executable forks` exits 1
  (selected ≠ adopted drift) and `build.py` treats it as fatal, so the build
  stops after writing `variants.json`. `seed_24` is runnable at the *simulation*
  level, as intended, but not through the build. Left alone: making the drift
  non-fatal is a policy change, and the drift report firing is correct.
* **The `[sims]` gate skips 38 steps by extra, not by artifact.** On a tree
  without `eml_spectral`, `build.py` skips every step marked `("sims", …)` —
  including all the downstream generators — *even when
  `AutoGenerated/parameters.json` is already present*. Measured here: the sims
  step itself ran fine standalone (exit 72) and produced all its artifacts, yet
  the build skipped every consumer. The generators were therefore invoked
  directly for this measurement.
* **`AutoGenerated/` under the CWD is not an export.** `autogen_dir()` falls
  back to `Path.cwd()/"AutoGenerated"` when `METAPHYSICA_OUT` is unset, so any
  module run ad hoc writes there — measured during this work: a concurrent
  fork-sweep test left `<repo>/AutoGenerated/variants.json` reporting
  `selected=seed_19_joyce`, a swept option, in the repository root. Harmless as
  scratch, but it means a path-purity check must not treat that directory as
  published output, and the gate does not.
* **`generate_js_constants` reports drift and changes nothing** (dry run without
  `--write`; `build.py` never passes it). It found and printed the drift it
  could not fix, and one missing mapping (`topology.chiEffective` →
  `geometry.chi_eff`).

## 6. The gate

`tests/test_export_active_path_only.py`, 12 tests. It restates no physics value:
both columns are computed from `b3_path.seed_values()` for the two named paths.

Always runs (no build needed):

* `test_the_gate_is_pointed_at_the_adopted_path` — the pins were measured
  against `seed_43_joyce`; if the ruling moves this fails first and says so. It
  also asserts the two columns differ for every checked quantity, so no verdict
  can be vacuous.
* `test_the_off_path_option_is_kept_and_stays_labelled` — `seed_24` must remain
  in `PATHS` with `reachable_by_joyce = False`.
* `test_the_verdict_function_separates_the_cases` — the detector must not put
  everything in one bin.
* `test_bundled_snapshot_verdicts_are_exactly_the_pinned_inventory` — 17 fields
  of `data/parameters.json` as an exact key → verdict map.
* `test_bundled_snapshot_off_path_count_cannot_grow` — 12, stated as a number.
* `test_bundled_constant_datasheets_leak_set_is_exactly_pinned` — exactly
  `{b3, k_gimel, w0}` of the 33.
* `test_frozen_writer_literals_are_exactly_the_pinned_inventory` — the five
  source fragments behind **B1/B2/B4**.
* `test_the_js_constants_step_still_cannot_repair_the_js_artifact` — pins the
  missing `--write`, the mechanism that keeps **B4** alive.

Runs when there is a **deliberate build target** — `METAPHYSICA_OUT`, or
`<repo>/site/` (the documented standard command's target). A bare
`AutoGenerated/` under the current directory deliberately does NOT count: it is
where individual modules scribble when run ad hoc, including the fork-sweep
tests in this same suite (see §5), so treating it as an export would make the
gate report another test's scratch file as a leak.

* `test_built_parameters_artifact_verdicts_are_exactly_pinned` — 10 ACTIVE,
  7 OFF_PATH, exact map.
* `test_a_built_export_carries_the_active_path_as_well_as_the_leak` — the
  positive direction on its own.
* `test_built_sections_prose_names_the_active_seed` — `42/43` and `b₃ = 43`
  must be in the prose, *and* the frozen `23/24` sentence must still be there
  until it is repaired.
* `test_the_fork_manifest_is_published_and_reports_the_adopted_seed` — the
  manifest must still list `seed_24` and must report `selected=seed_43_joyce`.

**It fails in every direction that matters, demonstrated:**

| Export it was run against | Result |
|---|---|
| the active-path build | 12 passed |
| no built artifacts (bare checkout) | 8 passed, 4 skipped |
| the `seed_24` build | **4 failed** — the pinned map, the missing active path, the prose with no `42/43`, the manifest reporting `seed_24` |
| the active-path build with `geometry.w_zero` / `cosmology.w0_derived` repaired to −42/43 | **1 failed** — the pin must be updated in the same change as the repair |

A pinned `ABSENT` is not a pass for an empty export: `ABSENT` is a distinct
verdict, so a field that stops being published fails the map equality.

`chi_eff` is deliberately **not** in the gate. 144 = 6 × 24 by
`geometric_anchors`' own formula, but `chi_eff_route` is forked OPEN and MUST
STAY UNRULED, and `b3_path.downstream()` reads `topology.mephorash_chi` as an
independent registry row rather than as 6 b₃. Calling it a leak would be
adopting that ruling. Recorded here as measurement only.

## 7. What remains open

1. **Nothing is repaired.** Every leak above is still in the export. A repair is
   a physics-touching change to `geometric_anchors.py` (the `b3=24`
   construction), `abstract.py` (the frozen sentence), `constant.py` (the
   snapshot precedence) and `build.py` (`--write`), and each one needs the pin
   updated with it.
2. **Which integer `dark_energy_betti` means** — `n = b_3` or `n = 24` — is
   unresolved, and the export publishes both answers in the same file (§3, C2).
3. **`geometry.wa`'s formula changed** between the bundled snapshot (−4/√b₃) and
   the live writer (−1/√b₃) and neither is labelled as superseding the other.
4. **`data/parameters.json` has no refresher at all.** No build step writes it;
   `generate_datasheets` reads it. It is 620 rows against a build's 798, and
   `parameter_artifact.py` measured 111 shared rows disagreeing on 2026-09-22.
5. **The build's `[sims]` gate skips consumers whose inputs exist** (§5), so a
   tree without `eml_spectral` publishes a partial site quietly.
6. **`metaphysica.build` cannot complete under the off-path override** (§5), so
   "`seed_24` stays runnable" is true of the simulations and not of the build.
7. The `certificates/**` tree (164 files) and `GATES_*.json` were not measured
   across seeds — they need `[sims]`, which is absent here.
