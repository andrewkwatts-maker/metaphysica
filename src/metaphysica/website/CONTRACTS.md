# Website JSON Contracts

The PrincipiaMetaphysica static site is a fetch-driven thin client: every JSON
artifact in `AutoGenerated/` is produced by exactly one Python module under
`metaphysica.generators` or `metaphysica.simulations`, and consumed by one or
more JavaScript files under `metaphysica.website.js` (or by inline `<script>`
blocks inside HTML pages).

The JS-side contract is fetch-based. Any new producer **must register its
output file here** so consumers can locate it, and any new consumer **must
declare the JSON file(s) it fetches** so the producer chain stays auditable.

Path convention: HTML pages under `Pages/` use relative paths
(`../AutoGenerated/foo.json`); top-level `index.html` and shared JS modules
prefer the site-root absolute form (`/AutoGenerated/foo.json`); JS loaders
typically try multiple candidates in order to support both local-static and
deployed contexts.

## Notes & Loose Ends

1. **`GATES_72_v16_2.json` rename**: Phase A.6 of the refactor renames this to
   `AutoGenerated/GATES_72.json`. Both producer (`generate_72gates_json.py`)
   and consumer (`generate_72_certificates.py`) must be updated atomically;
   `certificates.html` reads `GATES_CERTIFICATES.json` which transitively
   depends on the gates file.

2. **`foundations_registry.json` vs `foundations_data.json`**: the JS loader
   `pm-foundations-loader.js` probes for `foundations_data.json` first,
   while `Pages/foundations.html` hard-codes `foundations_registry.json`. A
   future consolidation should pick one canonical name and have the
   producer emit it.

3. **`wolfram_results.json`** is the only consumer-visible JSON with no
   in-tree Python producer — it is generated by an external Wolfram pipeline
   and dropped into `AutoGenerated/` manually. Treat it as an exogenous
   input and document the expected schema where it is consumed.

4. **`theory_output.json` is the union archive** — every split file
   (`formulas.json`, `parameters.json`, `sections.json`, …) is derived from
   it. Loaders that fail to find the split file fall back to
   `theory_output.json` (see `pm-formula-loader.js`, `pm-section-renderer.js`,
   `Pages/formulas.html` line 1944).

5. **`site-config.js`** centralises the canonical filenames as constants
   under `window.PMConfig.dataFiles`; new JSON files should be added here
   alongside the producer entry above.
